# Third-party notices

NanaType includes the interface materials, third-party fonts, shader compiler and Rust
crates below. Windows releases carry their complete licence texts as named
sections of `THIRD_PARTY_LICENSES.txt`, beside the executable. The filenames
below identify those sections:

| File | What |
| --- | --- |
| `LICENSE`, `LICENSE-MIT` | NanaType licensing scope and MIT licence for original code |
| `Bilibili-API-collect-CC-BY-NC-4.0.txt`, `Bilibili-NOTICE.md` | Original Bilibili protocol documentation source, attribution and inherited material scope |
| `DouyinLive-MIT.txt` | Douyin signing source, Copyright (c) 2025 今晚打打 |
| `FusionPixel12pxProportionalSC.LICENSE.txt`, `LXGWWenKai-Regular.LICENSE.txt`, `Tangerine-Bold.LICENSE.txt` | The fonts embedded for the built-in skins (also on the About page under "Open-source fonts"); Tangerine by Toshi Omagari, OFL-1.1 |
| `NotoSansSC-OFL.txt` | NanaUI's interface font |
| `KeySounds-CC0.txt`, `KeySounds-Bubble-CC-BY-3.0.txt` | The input window's keystroke sounds (mechanical keyboard, CC0 1.0; bubbles, CC BY 3.0), with their provenance |
| `rust-crates.txt` | Every Rust crate's own licence files, written at packaging time |
| `libvpx-BSD.txt` | libvpx VP9 decoder, distributed through shiguredo_libvpx |
| `dxc\` | The DirectX Shader Compiler's licence files, when the package was built from an official DXC release (see below) |

Font sources, versions and checksums are recorded in
[crates/theme/fonts/README.md](crates/theme/fonts/README.md). The Rust crate
list at the end is generated by `scripts/third-party-notices.ps1`; CI fails
when it is out of date or a crate has no licence expression.

On macOS, Syphon's Metal server is statically compiled by `nanalive-syphon`
from the pinned `sena-nana/nanalive-spout` repository. Its BSD-2-Clause shim,
the Syphon Framework's BSD-3-Clause licence, and the Metal server's millumin
copyright and redistribution terms are included from the crate's
`THIRD_PARTY_NOTICES.txt` in the `rust-crates.txt` section of
`Contents/Resources/THIRD_PARTY_LICENSES.txt`.

## Bilibili protocol code

The Bilibili live protocol documentation and WBI material come from
[SocialSisterYi/bilibili-API-collect](https://github.com/SocialSisterYi/bilibili-API-collect)
and its contributors, under **CC-BY-NC-4.0**, preserved by the accessible
[bilibili-plugins mirror](https://github.com/bilibili-plugins/bilibili-api-collect).
The inherited protocol comments and WBI material are adapted for NanaType;
they retain the upstream attribution, NonCommercial condition and disclaimer,
and are not covered by the MIT grant for original code. Full licence:
`crates/bilibili/LICENSE-API-COLLECT`, shipped as
`licenses/Bilibili-API-collect-CC-BY-NC-4.0.txt`.
See [crates/bilibili/NOTICE.md](crates/bilibili/NOTICE.md) (shipped as
`licenses/Bilibili-NOTICE.md`) for specific documents and the scope of changes.
The Bilibili crate and combined application declare `MIT AND CC-BY-NC-4.0`.

These interfaces and signing rules are sourced from existing community projects;
NanaType handles integration, porting and adaptation.

## Douyin native signing

The compact WebSocket signature and HTTP a_bogus byte layout in
`crates/douyin/src/signing.rs` are adapted into Rust from
[jwwsjlm/douyinLive](https://github.com/jwwsjlm/douyinLive), commit
`0e506f3cf935beede946296602af2e52d57ecea2`, specifically
`internal/webcastsign/native.go` and `sign/ab_sign.go`.
Copyright (c) 2025 今晚打打, MIT License. The full license ships as
`licenses/DouyinLive-MIT.txt` (source copy: `crates/douyin/LICENSE-DOUYINLIVE`).
The corresponding fixed WebSocket test vectors are attributed to
`internal/webcastsign/native_test.go` at the same revision.
The native connection parameter values and default push endpoint were also
checked against `websocket_params.go` and `constants.go` at that revision;
the Rust HTTP/WebSocket and reconnect implementation is maintained locally.

No dycast source, generated decoder, or extracted platform SDK is bundled.
Douyin connections, heartbeats, acknowledgements and decoding run in Rust.

## Telegram stickers

Telegram login, search and file downloads use the official MTProto API through
[grammers](https://codeberg.org/Lonami/grammers) (MIT OR Apache-2.0). TGS animations
are rasterized with [rasterlottie](https://github.com/neodyland/rasterlottie)
(MIT OR Apache-2.0); VP9 WebM frames use [libvpx](https://chromium.googlesource.com/webm/libvpx/)
(BSD-3-Clause) through [shiguredo_libvpx](https://github.com/shiguredo/libvpx-rs)
(Apache-2.0). The libvpx licence ships as `licenses/libvpx-BSD.txt`.
Downloaded sticker artwork belongs to its respective creators and is not bundled
with NanaType. Each downloaded pack retains its Telegram source link.

## Sounds embedded in NanaType

sets, both taken unmodified, apart from their names, from
[Tickeys](https://github.com/yingDev/Tickeys) (MIT), which ships them with their

mechanical set too; Keyda itself carries no licence, so nothing else of it is
used. Tickeys' other sets (sword, typewriter, Cherry G80) have no recorded
source and are not used.

dedicated to the public domain under **CC0 1.0**.

## DirectX Shader Compiler

The Windows package ships `dxcompiler.dll` beside `NanaType.exe`: Microsoft's
DirectX Shader Compiler (<https://github.com/microsoft/DirectXShaderCompiler>),
which NanaUI uses to compile its DirectX 12 shaders.

- Built from an official DXC release (`DXC_DLL` names its `bin\x64\dxcompiler.dll`):
  the compiler is open source; the repository's `LICENSE.TXT` is the
  University of Illinois/NCSA Open Source License (the LLVM release licence).
  The release archive's own licence files (`LICENSE*.txt` next to its `bin`
  folder) are authoritative: `scripts/package.ps1` copies them into
  `licenses\dxc\`, and refuses to package a release DLL without them.
- Otherwise the copy from the Windows SDK (`Windows Kits\10\bin\<version>\x64`)
  is shipped, under the Windows SDK licence terms for redistributable files;
  that SDK carries no separate licence file for it.
