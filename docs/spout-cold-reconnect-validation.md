# Spout 冷重连与设备复用

2026-10-17，继续 [5 秒快速重开验证](spout-reconnect-validation.md)。

## 实现和资源边界

Display、History 和 PeerDisplay 在同一 NanaUI 设备代次、同一适配器 LUID 上共用一个 D3D11 桥接设备和 immediate context。它由 `Rc` 管理，不能跨线程；发送、GPU wait/copy/signal 仍在原有窗口线程串行执行。每个 sender 自己持有 Spout 注册、共享面、导入的 DX12 纹理和共享围栏，销毁一路不会注销另一路。

关闭后的原有透明帧和 5 秒复用期限不变。5 秒到期会注销发送源，并释放各路图像资源；只额外保留一个不含图像或围栏的设备/context。最后一个有效输出关闭满 30 秒后也释放该设备。重复编辑、热重载、5 秒清理消息不延长这个期限。超过 30 秒再开启必须创建新设备。设备代次或适配器变化时清理旧 sender/import/cache。

输出启用后，在应用更新阶段创建 sender，已知固定尺寸时先发布一个透明面，让 OBS 发现和首帧渲染并行。尺寸跟随窗口时，设备和 sender 可以先准备，源注册仍等实际尺寸。准备不导入 producer 句柄、不消费围栏值、不重复清空已经活动的 sender。透明面准备失败则撤销该 sender，原有帧发布路径继续提供错误状态和回退。准备透明帧计入 SDK 的 sent_count，但不伪造 native producer 的发送或围栏记录。

进一步定位到 SDK 在每次 sender 构造时都枚举所有显示模式来取得刷新率，单路约 20 ms，而且返回的是最后一个支持模式。构建时在 `OUT_DIR` 的 SDK 副本上做精确函数替换，改为一次查询 `ENUM_CURRENT_SETTINGS`，不可用或未指定频率时仍回退 60 Hz。保留原始 SDK 版权及其余函数，不修改子模块检出；旧函数有变化时构建失败，要求显式审查兼容修正。此路径不增加长期缓存或 Windows 句柄。

中间验证还捕获到回收边界竞争：逐窗查询配置时读取实时毫秒，若恰好跨过 5 秒，一路先退役的状态回调可能取消另一路尚未退役的清理任务。配置现在只读取 `sync` 一次协调好的租期快照；到期清理由同一消息先移除所有过期 sender，再逐窗撤销配置。新增跨期限配置稳定测试，实际验收同时要求冷重连的原生池代次必须变化，快速重开则必须保持。

清理继续使用原有计时线程和单个清理任务。各路 sender 的 5 秒期限与设备的 30 秒期限取最早值；取消或到期后重新计算，不增加逐帧轮询或每次开关的线程。设备缓存只保留一个，应用退出释放全部持有者。

上述性能实测的 Spout 依赖固定到 [3b9283a5](https://github.com/sena-nana/nanalive-spout/commit/3b9283a599cfcf40f600afcba0740b1e8deb6a1e)，NanaUI 仍固定到 `3f521953f0cc4d4d4d853ee93aaf235af56bf5c7`。没有更改 Cargo 缓存或使用本地路径覆盖。

## 验证方法

同机 RTX 5060 / DX12 / 150% DPI，原有隔离便携 OBS 32.2.2、Spout 插件 1.12.0、1920×1080 / 60 fps。Display 960×320，History 960×360。插件发现轮询保持 100 ms，不修改轮询参数以缩短测试结果。只录本地测试源。

旧版 `run07-baseline` 为 8 次关闭 6 秒、1 次关闭 32 秒；最终版 `run11-final-cold` 为相同的 8 次关闭 6 秒，再做 3 次关闭 32 秒。两者都在全部原生窗口隐藏、相同潮汐皮肤下运行，最终关闭观察 35 秒。`run08-cold` 是修正 SDK 全模式枚举前的中间验证；`run10-final-cold` 和 `run09-regression` 在租期边界修正前，保留为定位证据，不作为最终版本验收。每轮在 1 秒和 6 秒查询 SDK 注册，检查先保留透明源、后注销；32 秒检查完全冷状态。像素恢复以录像首尾标记对齐单调时钟，误差约一帧（16.7 ms），围栏 1 ms 轮询是观测上界。

额外最终回归 `run12-final-regression` 覆盖多窗口可见/隐藏、12 次快速重开、切换主题、有效/无效 WGSL 热重载、3 次 6 秒与 1 次 32 秒关闭。监测器至多额外持有两路最后的 fence COM 引用，退出时释放；该观测代码只在 debug 样例安装，不进入发布版。实际测量结果见后续表格及 JSON。


## 实际 OBS 恢复时间

按相同的 8 次关闭 6 秒口径比较，单位 ms：

| 观测 | 旧版 Display | 新版 Display | 旧版 History | 新版 History |
| --- | ---: | ---: | ---: | ---: |
| OBS 恢复中位数 | 178.9 | 69.6 | 119.5 | 62.3 |
| OBS 恢复 P95 / 最大值 | 241.4 | 111.7 | 191.4 | 108.0 |
| 原生首帧发送恢复中位数 | 123.0 | 26.5 | 63.0 | 12.5 |

8 个样本中该 P95 算法取最大值；像素结果按约一帧精度理解。此前进度里的 182 / 112 ms 是旧版混合 6 秒与 32 秒共 9 次的统计，表中已统一比较口径。

新版 3 次关闭 32 秒后的完全冷启动，两路 OBS 恢复中位数均为 93.0 ms，最大 143.3 ms。对应原生首帧发送恢复中位数分别为 44 / 38 ms。旧版 32 秒只有一个样本（Display 228.9、History 112.2 ms），不据此声称稳定的百分比改善。OBS 插件仍有 100 ms 发现轮询，完全回收后也仍需创建设备和图像资源，不能保证零空白或每次都小于 100 ms。

最终混合回归的 12 次快速重开，Display / History 恢复中位数为 28.1 / 15.8 ms，P95 为 46.0 / 33.0 ms；全部复用原生池。该轮额外 3 次 6 秒冷重连中位数为 57.2 / 57.2 ms，1 次 32 秒完全冷启动为 111.8 / 111.8 ms。四套主题切换、三次有效与一次非法 WGSL 保存均完成，非法版本保留上一个有效效果。

两轮最终录像全部通过逐帧断言：每次关闭确实为空白，恢复后直到下一次主动关闭没有再闪空；新增 OBS 渲染和编码跳帧均为 0。最终冷录制 825 次、混合回归 1,105 次，共 1,930 次实际发送及围栏返回，pending、SDK failed/skipped/released-without-copy 均为 0。每个 sender 仅导入一份池。1 秒注册检查保留两个透明源，6 秒、32 秒及最终检查均无残留测试源。

原始录像共解码的帧数、逐轮数值、构造事件和资源采样见 [汇总 JSON](spout-cold-reconnect-validation.json)。

## 构造与资源回收记录

最终冷重连录制中，24 次 sender 构造的 CPU 中位数 0.224 ms、最大 0.622 ms；透明面准备中位数 0.682 ms、最大 1.84 ms。SDK 全模式枚举修正前的中间版对应 sender 构造中位数约 20.16 ms。设备只在首次启动和三次超过 30 秒的重开时创建，共四次；8 次 6 秒冷重连没有重复创建设备。设备创建本身中位数约 30.85 ms、最大约 44.28 ms，提前准备没有把这项成本伪装成消失。

四次设备到期事件分别发生在最后关闭后的 30,011、30,013、30,022、30,015 ms，均实际回收。每路 12 个 native 池代次符合初始池加 11 次冷重建，825 次实际发送及 825 次围栏返回，pending=0、错误=0。最终皮肤缓存只保留一个有界程序约 1.25 MiB，遮罩、参数绑定、缩放记录和编译队列均为零；全程仅编译一次该皮肤程序。

冷重连重复阶段的 49 个采样中，应用句柄为 752–790，最终回落到 617；线程为 60–64，最终 33。私有内存稳定在约 636.26–636.51 MiB，最终约 627.06 MiB。OBS 私有内存约 551.34 MiB，最终约 259.59 MiB，句柄最终 2,272。

多主题混合回归后，应用句柄回落至 664、线程 38；该轮冷重连阶段的 10 个采样私有内存约 804.29–805.29 MiB，最终约 803.19 MiB。保留 11 个有界效果程序约 13.75 MiB，所有效果实例遮罩、参数绑定、缩放记录和编译队列均为零。皮肤程序共编译 11 次，对应预热和有效源码变化，开关期间不逐帧重编译。两轮均未观察到随重复次数持续增长的句柄、线程或发送源。

最终确认 OBS 两路发现间隔仍为 100 ms、录制已停止、测试来源全部注销；已关闭本任务启动的便携 OBS 和测试应用。

## 自动回归与复现

Spout 库 9 项测试通过，涵盖两路共用一个设备、反复销毁/重建一路后另一路继续发送、无 producer 池的透明准备、最后一个持有者退出后的引用释放、池代次和外适配器拒绝，以及刷新率兼容修正的精确匹配/CRLF/SDK 变化拒绝。应用最终单元回归 167 通过，2 项原有忽略。

构建包含主程序及真实 Host 的 `native_outputs` 样例，使用锁定依赖与前一报告的相同 dev 优化参数。仍有既有 libvpx 缺少 PDB 的链接警告。设备代次变化有失效处理，但本次没有 GPU 驱动故障注入或跨适配器实际接收测试。

```powershell
python scripts/run-obs-spout-reconnect.py <cold-run> --cold-only --cold-rounds 8 --full-expiry --full-expiry-rounds 3
python scripts/run-obs-spout-reconnect.py <regression-run> --warm-rounds 4 --full-expiry
python scripts/analyze-spout-reconnect.py <cold-run>
python scripts/analyze-spout-reconnect.py <regression-run>
python scripts/report-spout-cold-reconnect.py <baseline-run> <cold-run> <regression-run>
```

每个目录使用独立 app/data 和本地 commands 队列；先按前一报告启动隔离 OBS 与 `native_outputs`，不复用个人应用数据。原始记录位于 `E:/NanaType-validation-classic-20261017/obs/`。短时重复测试可观察资源回落和是否随次数累积，不把驱动/分配器暂未归还的全部私有内存单独当作泄漏证据，也不把有界复用承诺为无限期无缝重连。


## 交付整理

交付版将 Spout 依赖更新到 [72352c0](https://github.com/sena-nana/nanalive-spout/commit/72352c0da9bec2e11c2f4f6b28ddfd020525fbb7)。发送器与共享设备只保留一份适配器身份；透明准备和普通发布共用同一套结果、尺寸与计数处理。应用将预准备与逐帧路径的复用检查收敛到一个入口，只解析一次待准备的输出，并以固定栈数组传递共享句柄。绘制调度也只计算一次打字、扫光和跟随状态。

5 秒图像资源期限、30 秒设备期限、失败静态回退和 WGSL 限制不变。上游 9 项测试通过；交付版完整工作区默认并发运行 434 项通过、4 项忽略，格式、全目标严格 Clippy 和 573 个依赖的许可证清单检查均通过。旧图片回归更新为验证内容地址复用、原地替换后的刷新、旧引用保留原图，以及水墨静态框体和墨竹素材的继承加载。

补充真实 OBS 录制 `run13-simplified` 使用交付版依赖，覆盖显示和隐藏原生窗口、四套皮肤切换、3 次有效及 1 次无效热重载、12 次快速重连、2 次 6 秒冷重连和 1 次 32 秒完全冷重连。1044 次发送与释放一一对应，无错误或遗留；快速重连全部复用原池，冷重连全部更换池，关闭均只提交一次透明帧。逐帧分析未发现恢复后再次空白，OBS 新增渲染丢帧与编码丢帧均为零。

本轮 OBS 恢复中位数：快速重连主展示 / 历史为 25.9 / 18.0 ms；6 秒冷重连两路均为 90.9 ms；32 秒完全冷重连两路为 107.4 ms。这里的冷重连样本较少，用于交付回归，不替代上文同 8 轮基线的性能比较。视频采样精度约一帧。

两次设备回收发生在关闭后 30024 / 30019 ms，最终 OBS 中测试发送源为零，应用句柄与线程回落到 686 / 42。最终保留 11 个有界程序缓存（13.75 MiB），遮罩、实例 uniform、缩放缓存与待编译任务均为零。录制已停止，测试应用和本任务的便携 OBS 已退出。完整补充数据见 JSON 的 `delivery` 字段。
