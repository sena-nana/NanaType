# 包编辑器

对应 [#6](https://github.com/sena-nana/NanaType/issues/6)，格式与边界见[统一包整体设计](package-design.md#包编辑器)。编辑器是独立程序 **NanaType Editor**（`editor/`，单独构建、单独安装），与 NanaType 共用 `crates/frame` 中的皮肤渲染器、界面组件和插件宿主，但互不包含对方的代码、文案和资源：NanaType 中没有编辑入口，编辑器中也没有弹幕、联机、贴纸、输出和热键。

编辑器支持内部草稿和直接写回的目录工程：当前皮肤、已安装的包、插件同意和运行中的插件都不会因为编辑而变化。导出 `.ntpkg` 再在 NanaType 的“设置 → 插件与资源包”中导入后，修改才会生效。

## 界面布局

打开工程后，窗口是以画布为中心的工作区（最小 960×600 逻辑像素，初始 1440×900）：

- **工具栏**：包名（点开为工程菜单：撤销到上次保存、关闭）、包类型、撤销／重做；显示画布的工作区还有布局目标（基础、横版、竖版、断点规则）、视口尺寸预设和展示／历史／输入视图；右侧是“画布旁显示源码”或“显示实时预览”开关、导出和保存。只有“保存”在有未保存修改时使用强调色。
- **活动栏**：设计、文件、音效、数据与管线、Lua；底部是包信息、保护与签名。工程没有对应能力时不显示该入口（例如纯皮肤包没有 Lua）。再次点击当前入口可以收起或展开左侧面板。
- **左面板／中央区／右检查器**：随工作区变化，两侧面板可以拖动调整宽度，切换工作区时保留宽度。窗口窄于 1280 逻辑像素时左面板默认收起。
- **底部抽屉**：问题列表（点击跳到文件和行）和 Lua 调试记录，默认收起，从状态栏打开。
- **状态栏**：问题数、调试记录入口、工程来源，以及保存、校验和签名状态。

颜色跟随系统明暗，画布区始终使用中性底色。

## 数据目录

编辑器读写 NanaType 的数据目录（Windows `%APPDATA%\dev.sena-nana.nanatype`，macOS `~/Library/Application Support/dev.sena-nana.nanatype`），启动页显示当前路径：

- `packages/`：NanaType 已安装的包，只读，用于编辑副本、复制和打包依赖；
- `package-drafts/`：手动保存的草稿，`recovery/` 下为独立的自动恢复快照；
- 签名密钥（DPAPI 文件或钥匙串 `dev.sena-nana.nanatype.package-signing`），以前在 NanaType 中创建的密钥可以继续使用；
- `config/settings.json`：只读，默认按包自身默认值预览；显式启用“模拟 NanaType 个人配置”后才使用个性化，不写回工程。

便携版 NanaType 的数据在其程序旁的 `data/` 中，用 `nanatype-editor --data <该目录>` 指定。便携版编辑器自身也使用程序旁的 `data/`。命令行 `nanatype-editor <文件.ntpkg 或工程目录>` 直接打开工程；再次启动会把绝对路径转交给已打开的窗口，并经过相同的未保存确认，NanaType 与编辑器可以同时运行。

## 打开工程

启动页列出新建、打开、草稿和 NanaType 已安装的包：

- **新建**：选择纯皮肤、纯资源、纯 Lua、纯音效包或混装，填写包 ID。模板可以直接通过校验。
- **打开工程目录**：选择包含 `package.toml` 的根目录，保存写回该目录。安装包目录不可作为可写工程，目录扫描排除版本控制目录并拒绝符号链接。
- **打开 .ntpkg**：损坏的包也能打开以便修复。签名校验失败时，本地文件全部只读。
- **编辑**（已安装的用户包）：从安装目录读取一份副本，安装目录本身不被改写。
- **复制为新包**（任意包，包括内置包）：生成使用新 ID 的衍生副本，去除原签名，并写入 `derived_from`。

在 NanaType 中安装新包后，点“重新加载”刷新列表。已知包 ID 的变更需要“复制为新包／派生副本”，源码修改也遵守这一限制；派生前需处理未提交表单，并统一经过未保存确认。

## 文件

“文件”工作区左侧是文件树，锁形图标表示受签名保护，`dependencies/` 下是依赖包，均为只读；树顶部提供导入、新建／移动／替换和删除。中央是所选文件，右侧可以保留实时预览。文本文件在带行号的编辑器中打开：

- Lua、TOML、WGSL 支持缩进和注释切换。
- 搜索不区分大小写，支持前一处、下一处、替换当前及全部替换；每文件保留光标、选区和滚动状态。
- TOML 和 JSON 可以格式化，注释和键的顺序保持不变。

二进制文件显示按内容识别的格式、大小、BLAKE3 摘要，以及数据声明中的来源和许可。

文件可以新建、移动、重命名、替换和多选导入。目标路径栏指定新建或重命名后的目录；导入使用发起时所选文件的目录（根目录文件默认导入 `assets/`）。重命名会展示引用影响，自动更新已识别的声明路径；Lua／WGSL 中的字符串只提示人工同步，受保护引用会阻止操作。

图片支持透明棋盘背景和已声明九宫格辅助线；字体显示示例文字；音频显示时长并提供播放、停止、音量，只有显式播放时才启动音频设备。

导入素材时保留文件名，宿主会检查路径、大小，以及扩展名与内容是否一致，例如 `.png` 必须真是 PNG。

输入后完整校验防抖 300ms，只保留一个后台任务并合并到最新版本；错误时保留上一有效预览并标记过期。超过 64 KiB 的源码语法诊断及大皮肤的管线列表交给后台更新，输入路径保留轻量检查。完整校验与导入走同一路径，在后台运行，覆盖依赖、签名、皮肤、数据和脚本入口。点击“问题”列表中的一项，会跳到对应文件和行。

## 包信息

表单可以修改以下字段，写回 `package.toml` 时保留其他内容与注释：

- 多语言名称与描述、标签、封面、最低版本、基础皮肤
- 版本、作者、制作日期、授权对象、许可证
- 能力
- 依赖，每行一个 `包ID@精确版本`，支持从已安装包选择；缺版本、重复 ID、非法版本逐行报错，禁止静默忽略

启用皮肤或 Lua 能力时会补上起始文件。依赖从已安装的包打包进草稿。

声明的数据和处理管线在“数据与管线”工作区用表单增删改：

- **数据**（`package.toml` 的 `[data.<id>]`）：ID、文件路径、格式、格式版本、来源、许可，以及只用于 JSON 的约束（填 JSON 对象，留空表示不限制）。文件必须已在包内。改名时 `[lua] reads` 跟着改。
- 声明数据的即时诊断、格式化入口和编辑模式按 `format` 决定：文本使用 `.json` 文件名不会误报 JSON 错误，JSON 使用 `.txt` 文件名也能格式化。
- **管线**（`skin.toml` 的 `[pipelines.<名称>]`）：名称、处理器、各输入端口和参数。条目同时列出注册处理器的输出名称与类型。输入写数据 ID（依赖包的数据写 `pkg:包ID/数据ID`），或写 `管线名.输出` 接入另一条管线；参数每行一个 `名称 = 数值`。

未提交的表单内容（包括非法输入）保存在工程会话中，切换页签不会丢失，纳入未保存提示及恢复快照；保存和导出前须应用或放弃这些输入。

写入前先严格解析 `package.toml`，并按已注册的处理器检查管线（端口类型、环、深度、参数范围、引用的数据是否声明及格式是否匹配、材质是否失去来源）。这次修改新增了错误时不写入，并给出提示。写回时在原位修改，其他键和注释保留。`package.toml` 或 `skin.toml` 受签名保护时，对应部分只读。无法解析的管线照常列出，并注明需要在源码中修改。

## 保护与签名

首次签名时选择“使用本机签名密钥”，没有密钥时再创建。私钥只存放在系统的受保护存储中：macOS 用钥匙串，Windows 用 DPAPI。它不会进入包、日志或插件，其他平台目前不支持签名。

勾选要保护的文件后签发，`package.toml` 始终受保护。签名后：

- 受保护文件只读，文件清单固定。
- 可编辑文件修改后，签名状态仍如实显示为有效。
- 用本机密钥签发的包可以移除签名，修改后重新签发。
- 用其他密钥签发的包只能复制为衍生副本后再修改。

签名只说明内容与签名时一致，不证明作者身份。

## 预览

预览就是“设计”工作区中央的画布。画布上方是播放模式（静态、播放、减少动态、关闭高级效果）、重播、缩放与适应窗口、背景，以及画布设置（自定义逻辑宽高、模拟 NanaType 个人配置）和当前命中的布局层；下方是示例说话人和测试文本。工具栏选择视口预设（横版、竖版、窄窗、默认尺寸）和视图。静态、播放、减少动态、关闭高级效果及重播均使用私有 Stage，离开画布后不持续刷新。

皮肤通过校验后，用实际的渲染器绘制草稿，可以在三种视图之间切换：

- **展示**、**历史**：与设置中的皮肤预览相同。
- **输入**：输入窗口开启皮肤预览时的输入框（`dialogue` 的 `Source::Draft`），里面是一份私有的示例草稿。示例编辑器不能获得焦点，也不接受输入，不发送任何消息。

预览与 NanaType 的皮肤页使用同一个 `nanatype_frame::ui::preview::stage`，每个样例都在私有的 `Stage` 上绘制。“文件”工作区右侧的实时预览也使用这一画布。

## 属性与画布

“设计”工作区左侧是**图层**：`skin.toml` 中声明的表（含继承的默认值）按层级列出，对话框在最前，数组表（如装饰）按序号列出；下方是预览参数，只修改测试取值。选中图层时，右侧**检查器**显示这张表的值，画布同时选中它绘制的部件（姓名牌、头像、继续标识、装饰）；在画布上点选部件也会选中对应图层。

检查器每个值一行：本地声明的标签用强调色，继承值为次要色；数字可以拖动调整（一次拖动只提交一次撤销），颜色带取色器，其他值输入后点“应用”，“恢复继承”删除本地声明，链接图标打开参数绑定。子表在行尾列出，可以逐级进入；“新增字段”提供参数、分组、预设和响应式模板。

**高级皮肤**以源码为准：工具栏的“画布旁显示源码”把中央区分为画布和 `skin.toml`／WGSL 源码，选中图层时源码滚动到对应的表；检查器底部的“本节 TOML”显示这张表（及其子表）在源码中的整块内容，就地修改后只替换这一块，其他内容与注释逐字保留；没有单独表头的表提示在所在的表中修改。着色器、材质、参数、分组和预设都作为图层出现。

画布支持单元素选择、装饰移动／缩放、姓名牌／头像／继续标识移动；装饰的新增、复制、删除和排序在图层面板顶部。方向键移动，Shift 增大步长，Esc 或窗口失焦取消拖动；一次拖动只提交一次撤销记录。

编辑目标可选基础、横版、竖版或断点规则。属性显示本地覆盖与继承值，“恢复继承”删除本地声明，预览显示当前命中层的应用顺序。数组首次覆盖复制当前层的完整有效数组；布局几何来自真实渲染节点，手势按预览缩放换算，保留百分比长度。拖动提交前会比较实际解析结果；选定层被其他响应式层覆盖时拒绝写入并提示切换目标。参数绑定需要显式解除后才能改为常量；WGSL 内部图形仍由源码编辑。

断点规则布局沿用运行时的字面量限制；继承数组含参数绑定时，向规则层提交会被完整校验拒绝，保留原稿。横竖版布局可保留参数绑定。

局部声明修改使用 `toml_edit`，保留其他字段、注释、未知字段和参数占位；源码语法错误时暂停对应可视化操作，可继续在源码页修复。音效页复用声明属性编辑及素材试听；没有着色器节点图或 Lua 断点调试器。

## Lua 调试

调试按以下规则运行：

- 后台完整校验使用独立 Wasm 工作进程只编译 Lua，不执行源码，无需脚本信任。
- 实际运行前先阅读风险说明，再勾选“信任当前源码”，才能启动。
- 脚本运行在与正式插件相同的独立 Wasm 工作进程中，受同样的沙箱和限额约束；工作进程由编辑器以 `--plugin-worker` 重新启动自身得到。
- 系统进程的启动与回收在后台进行；启动失败会显示错误，停止或修改后忽略旧结果。
- 调试器只发送你选择的测试事件（`line_start`、`line_end`、`speaking`、`chat_message` 或自定义 JSON），支持可编辑事件序列重播和日志筛选。
- 返回的视图与命令只显示在调试面板中。
- 修改任何文件都会停止脚本并撤销信任，脚本不会自动运行。
- 死循环、超出预算的视图和语法错误都会以错误结束，不会卡住界面。
- 错误行号会映射回入口文件，可以点击定位。

## 保存与导出

| 操作 | 行为 |
|---|---|
| 保存 | 草稿写入 `package-drafts/`，目录工程写回源目录；源码不要求先通过校验，待提交表单需先处理 |
| 撤销到上次保存 | 放弃之后的所有修改 |
| 关闭／退出／打开另一工程 | 统一询问保存、放弃、取消；保存完成后执行对应操作，期间的新修改仍保留未保存状态 |
| 丢弃草稿 | 需要二次确认，只删除草稿，不影响已安装的包 |
| 导出 .ntpkg | 打包依赖并完整校验，失败时不写文件 |

草稿、恢复快照和导出采用同目录临时文件加原子替换；写失败保留旧文件。保存、素材读取、完整校验的摘要和密钥访问在后台执行，结果携带工程标识及版本。全局撤销／重做涵盖源码、表单、文件、签名及画布，签名与保护状态随内容恢复。

编辑停止 2 秒后写入恢复快照，不覆盖手动保存点；重新启动在首页选择恢复或丢弃。目录工程的快照分别保留手动保存点、源路径和最新磁盘基线，恢复后重新检查外部变更。

目录监听将突发事件合并；未修改文件跟随磁盘，不同文件修改合并，同文件冲突提供保留本地、接受磁盘或另存副本。保存前重新核对基线，冲突未处理时禁止覆盖。多文件保存使用应用数据目录的 `directory-transactions/` 日志和备份，中断后再次打开会恢复；如恢复与新的外部修改冲突，保留日志并报告路径供人工处理。

macOS 包声明 `.ntpkg` 文档类型并处理 Finder 打开事件；Windows 安装器提供“打开方式”注册而不替换用户默认应用。命令行也接受目录路径。
