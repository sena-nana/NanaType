# NanaType Editor

NanaType Editor 是独立的包制作工具，用于创建、编辑、预览、签名和调试 NanaType 包。

它与 NanaType 共用皮肤渲染器和插件宿主，但职责不同：

- 编辑器负责制作包，不负责弹幕、联机、贴纸、OBS 输出或全局热键。
- 编辑过程只影响草稿或工程目录，不会直接改动 NanaType 当前使用的皮肤和插件。
- 导出 `.ntpkg` 后，在 NanaType 的“设置 › 插件与资源包”中导入，修改才会生效。

包格式和安全边界见[统一包整体设计](package-design.md)。

## 入门

### 启动与打开工程

启动页提供以下入口：

- **新建**：纯皮肤、纯资源、纯 Lua、纯音效或混装工程。
- **打开工程目录**：选择包含 `package.toml` 的目录，保存时写回原目录。
- **打开 `.ntpkg`**：损坏的包也可以打开修复；签名校验失败时文件只读。
- **编辑已安装包**：编辑器读取副本，不改写安装目录。
- **复制为新包**：使用新 ID 创建衍生副本，移除原签名并写入 `derived_from`。

打开工程后，编辑器会持续显示保存、校验、签名和来源状态。切换到其他工程前，未保存的修改会要求确认。

### 第一次制作

推荐流程：

1. 新建包并填写包 ID、版本、作者和许可证。
2. 在“文件”工作区添加 `skin.toml`、图片、字体、音效或 `main.lua`。
3. 在“设计”工作区调整皮肤并用展示、历史、输入三种视图预览。
4. 在“数据与管线”工作区声明数据资源和处理管线（需要时）。
5. 解决“问题”列表中的错误，再保存或导出。
6. 如需发布，在“发布”中选择受保护文件、签名并导出。

在一行里输入的值，按 Enter 或离开该字段时写入；勾选、下拉和取色在选择时立即写入。未能写入的内容会保留，切换页签、校验或恢复快照不会丢失输入。

## 操作

### 工作区

- **设计**：编辑图层、响应式布局和预览参数。
- **文件**：查看、编辑、导入、移动、替换和删除包内文件。
- **音效**：把打字音、对话开始／继续和命名音效绑定到包内音频，逐行试听；右栏是选中文件的播放器。
- **数据与管线**：左侧列出 `[data.<id>]` 和 `[pipelines.<name>]`，中间编辑选中的一项。
- **Lua**：左侧是 Lua 源码，中间编辑，右栏是调试器（测试事件与返回的视图），日志在底部抽屉。
- **包信息**：设置元数据、能力、依赖和封面。
- **发布**：自上而下依次是校验、签名状态与本机密钥、受保护的文件、导出。

所有工作区使用同一套布局：左侧活动栏切换工作区，左面板列出对象，中央是编辑器、表单或预览，右栏是当前选中项的属性，底部“问题”抽屉定位错误并可拖动调整高度。预览的视图、尺寸、动态、缩放、背景和示例文本都在画布上方的一条工具条里。窗口窄于 1280 逻辑像素时左面板默认收起。每个工作区会回到自己上次打开的文件。

### 快捷键

Windows 用 Ctrl，macOS 用 ⌘：

| 按键 | 操作 |
| --- | --- |
| `Mod+S` / `Mod+E` | 保存 / 导出 |
| `Mod+Z` / `Mod+Shift+Z` | 撤销 / 重做（焦点在文本框内时使用文本框自己的撤销） |
| `Mod+F` | 在源码中查找和替换，Esc 关闭 |
| `Mod+1` … `Mod+7` | 按活动栏顺序切换工作区 |
| `Mod+B` / `Mod+J` | 显示或隐藏左面板 / 问题抽屉 |
| `Mod+W` | 关闭工程 |
| `F5` / `Shift+F5` | 启动 / 停止 Lua 调试 |

保存会等待正在写入的修改，所以在字段里直接按 `Mod+S` 不会丢掉刚输入的内容。

### 编辑文件与素材

文本编辑器支持 Lua、TOML 和 WGSL：

- 搜索、替换、格式化 TOML / JSON，并保留注释和键顺序。
- 每个文件保留光标、选区和滚动位置。
- 重命名时显示引用影响，并自动更新已识别的声明路径。
- Lua 和 WGSL 中的字符串引用只提示人工同步；受保护引用会阻止操作。

导入素材时会检查路径、大小和扩展名是否与真实格式一致。图片支持透明棋盘和九宫格辅助线；字体显示示例文字；音频只在点击试听时启动音频设备。

完整校验在后台运行，覆盖依赖、签名、皮肤、数据和脚本入口。校验出错时保留上一份有效预览，并可从“问题”列表跳到文件和行。

### 编辑包信息、数据与管线

“包信息”表单可以修改：

- 多语言名称、描述、标签和封面；
- 版本、作者、制作日期、授权对象和许可证；
- 最低应用版本、基础皮肤和能力；
- 依赖（每行一个 `包ID@精确版本`）。

启用皮肤或 Lua 能力时，编辑器会检查入口文件；依赖可以从已安装包选择，并在导出时打包到 `dependencies/<包ID>/`。

“数据与管线”中的字段会写回源码：

- **数据**：ID、路径、格式、格式版本、来源、许可证和 JSON 约束。支持 `text`、`json`、`nthz`。
- **管线**：注册处理器、输入、输出和参数。输入可以是数据 ID 或 `管线名.输出`。

写入前会检查未知字段、类型、循环、参数范围、依赖和受保护内容。保存失败时不会覆盖旧文件。

### 预览与布局

预览使用 NanaType 的真实渲染器，可切换：

- 展示框、历史记录和输入框视图；
- 静态、播放、减少动态和关闭高级效果；
- 横版、竖版、窄窗和自定义尺寸；
- 基础布局、响应式布局和断点规则。

画布支持选择图层、移动或缩放装饰、移动姓名牌／头像／继续标识。方向键微调，Shift 加大步长，Esc 取消拖动。一次拖动只生成一条撤销记录。

检查器中的“恢复继承”会删除本地覆盖。高级皮肤可在源码面板中直接编辑 `skin.toml` 与 WGSL；编辑器保留其他字段、注释和未知字段。

### Lua 调试

调试前必须阅读风险说明并确认“信任当前源码”。调试器：

- 在独立 Wasm 工作进程中运行，使用与正式插件相同的沙箱和限额；
- 只发送你选择的 `line_start`、`line_end`、`speaking`、`chat_message` 或自定义 JSON 事件；
- 只在调试面板显示返回的视图和命令，不接入正式插件槽位；
- 修改任何文件都会停止脚本并撤销信任；
- 死循环、非法视图、超出预算和语法错误会结束调试，不会卡住界面；
- 错误行号可定位回入口文件。

调试确认不等于安装启用同意。导出并导入后，仍需在 NanaType 中重新审查和启用。

### 保存、恢复与导出

| 操作 | 结果 |
| --- | --- |
| 保存 | 草稿写入 `package-drafts/`，目录工程写回源目录；源码可暂时不通过校验 |
| 撤销到上次保存 | 放弃保存点之后的修改 |
| 关闭或打开其他工程 | 询问保存、放弃或取消 |
| 丢弃草稿 | 二次确认，只删除草稿 |
| 导出 `.ntpkg` | 打包依赖并完整校验；失败时不写文件 |

停止编辑约 2 秒后会生成恢复快照。重新启动时可以恢复或丢弃。目录工程保存前会检查外部修改；冲突未处理时禁止覆盖。

## 参考

### 数据目录与命令行

编辑器使用 NanaType 数据目录：

- Windows：`%APPDATA%\\dev.sena-nana.nanatype`
- macOS：`~/Library/Application Support/dev.sena-nana.nanatype`
- 已安装包：`packages/`
- 草稿与快照：`package-drafts/` 和 `package-drafts/recovery/`

便携版可以用 `nanatype-editor --data <目录>` 指定数据目录，也可以直接运行 `nanatype-editor <文件.ntpkg 或工程目录>` 打开工程。

### 签名与保护

- 私钥只保存在 macOS 钥匙串或 Windows DPAPI 中，不写入包、日志或插件。
- `package.toml` 始终受保护；其他文件可按需选择保护。
- 使用本机密钥签名的包可以移除签名后重新签发；其他签名只能复制为衍生副本后修改。
- 签名表示内容与公钥匹配，不代表作者身份，也不是加密或 DRM。

### 验证与当前状态

编辑器的单元、可靠性、界面和导出验证由 CI 与编辑器测试维护。平台原生窗口、DPI、IME、系统文件选择器、钥匙串／DPAPI 和最终安装包仍需按平台单独验收；不在本页维护日期、测试计数或性能实验记录。

插件隔离、预算与性能测量见[插件性能、预算与隔离](plugin-performance.md)。
