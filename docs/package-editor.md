# 包编辑器

对应 [#6](https://github.com/sena-nana/NanaType/issues/6)，格式与边界见[统一包整体设计](package-design.md#包编辑器)。编辑器在“设置 → 插件与资源包”中，只修改草稿：当前皮肤、已安装的包、插件同意和运行中的插件都不会因为编辑而变化。导出 `.ntpkg` 再导入后，修改才会生效。

## 打开工程

- **新建**：选择纯皮肤、纯资源、纯 Lua 或混装，填写包 ID。模板可以直接通过校验。
- **打开 .ntpkg**：损坏的包也能打开以便修复。签名校验失败时，本地文件全部只读。
- **编辑**（已安装的用户包）：从安装目录读取一份副本，安装目录本身不被改写。
- **复制为新包**（任意包，包括内置包）：生成使用新 ID 的衍生副本，去除原签名，并写入 `derived_from`。

## 文件

左侧文件树中锁形图标表示受签名保护，`dependencies/` 下是依赖包，均为只读。文本文件在带行号的编辑器中打开：

- Lua、TOML、WGSL 支持缩进和注释切换。
- 搜索不区分大小写，“下一个”会选中下一处匹配。
- TOML 和 JSON 可以格式化，注释和键的顺序保持不变。

二进制文件显示按内容识别的格式、大小、BLAKE3 摘要，以及数据声明中的来源和许可。

导入素材时只保留文件名，宿主会检查路径、大小，以及扩展名与内容是否一致，例如 `.png` 必须真是 PNG。

每次输入都会检查语法。完整校验与导入走同一路径，在后台运行，覆盖依赖、签名、皮肤、数据和脚本入口。点击“问题”列表中的一项，会跳到对应文件和行。

## 包信息

表单可以修改以下字段，写回 `package.toml` 时保留其他内容与注释：

- 版本、作者、制作日期、授权对象、许可证
- 能力
- 依赖，每行一个 `包ID@精确版本`

启用皮肤或 Lua 能力时会补上起始文件。依赖从已安装的包打包进草稿。

声明的数据和处理管线也用表单增删改：

- **数据**（`package.toml` 的 `[data.<id>]`）：ID、文件路径、格式、格式版本、来源、许可，以及只用于 JSON 的约束（填 JSON 对象，留空表示不限制）。文件必须已在包内。改名时 `[lua] reads` 跟着改。
- **管线**（`skin.toml` 的 `[pipelines.<名称>]`）：名称、处理器、各输入端口和参数。输入写数据 ID（依赖包的数据写 `pkg:包ID/数据ID`），或写 `管线名.输出` 接入另一条管线；参数每行一个 `名称 = 数值`。

写入前先严格解析 `package.toml`，并按已注册的处理器检查管线（端口类型、环、深度、参数范围、引用的数据是否声明及格式是否匹配、材质是否失去来源）。这次修改新增了错误时不写入，并给出提示。写回时在原位修改，其他键和注释保留。`package.toml` 或 `skin.toml` 受签名保护时，对应部分只读。无法解析的管线照常列出，并注明需要在源码中修改。

## 保护与签名

首次签名时选择“使用本机签名密钥”，没有密钥时再创建。私钥只存放在系统的受保护存储中：macOS 用钥匙串，Windows 用 DPAPI。它不会进入包、日志或插件，其他平台目前不支持签名。

勾选要保护的文件后签发，`package.toml` 始终受保护。签名后：

- 受保护文件只读，文件清单固定。
- 可编辑文件修改后，签名状态仍如实显示为有效。
- 用本机密钥签发的包可以移除签名，修改后重新签发。
- 用其他密钥签发的包只能复制为衍生副本后再修改。

签名只说明内容与签名时一致，不证明作者身份。

## 预览

皮肤通过校验后，用实际的渲染器绘制草稿，可以在三种视图之间切换：

- **展示**、**历史**：与设置中的皮肤预览相同。
- **输入**：输入窗口开启皮肤预览时的输入框（`dialogue` 的 `Source::Draft`），里面是一份私有的示例草稿。示例编辑器不能获得焦点，也不接受输入。当前输入窗口的草稿、编辑器内容和皮肤都不会改变。

所选视图只属于编辑器，不影响设置中皮肤页的选择。

## Lua 调试

调试按以下规则运行：

- 先阅读风险说明，再勾选“信任当前源码”，才能启动。
- 脚本运行在与正式插件相同的独立 Wasm 工作进程中，受同样的沙箱和限额约束。
- 调试器只发送你选择的测试事件（`line_start`、`line_end`、`speaking`、`chat_message` 或自定义 JSON）。
- 返回的视图与命令只显示在调试面板中。
- 修改任何文件都会停止脚本并撤销信任，脚本不会自动运行。
- 死循环、超出预算的视图和语法错误都会以错误结束，不会卡住界面。
- 错误行号会映射回入口文件，可以点击定位。

## 保存与导出

| 操作 | 行为 |
|---|---|
| 保存草稿 | 写入数据目录下的 `package-drafts/`，不要求先通过校验 |
| 撤销到上次保存 | 放弃之后的所有修改 |
| 关闭 | 有未保存的修改时，询问保存并关闭、不保存关闭或取消 |
| 丢弃草稿 | 需要二次确认，只删除草稿，不影响已安装的包 |
| 导出 .ntpkg | 打包依赖并完整校验，失败时不写文件 |

## 验证

```sh
cargo test -p nanatype-theme editor
cargo test -p nanatype --test package_editor
```

界面测试会在 `target/package-editor/` 下生成截图，覆盖中文、英文、日文三种语言，900／440／300px 三种宽度，以及文件、包信息（含展开的数据与管线表单）、签名、调试、预览（含输入窗口）各页。
