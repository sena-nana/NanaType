# 彗星号との連携

[彗星号](https://huixinghao.cn/)は配信補助ツールです。そのクリエイティブワークショップのプラグインはすべて静的な Web ページで、彗星号のキャンバス内の iframe で動作し、`window.postMessage` で配信ルームのイベントを受け取ります（[開発ドキュメント](https://gitee.com/t_tgl/hxh-dev-docs)、中国語）。NanaType はプラグインページでこれらのイベントを転送し、blivechat プロトコルで受信します。blivechat サーバーに接続するときと同じ経路です。

## データの流れ

```
彗星号客户端 / OBS 浏览器源
  └─ 插件页面 integrations/comet/index.html
       postMessage 收到 LIVE_OPEN_PLATFORM_DM / SEND_GIFT / SUPER_CHAT / GUARD
       toBlivechat() 转换成 blivechat 帧 {cmd, data}
       │  ws://127.0.0.1:12451/comet?token=…   （页面主动连本机）
       ▼
NanaType 中转（crates/blive/src/relay.rs）
       校验 token，按消息 id 去重，转发给 /api/chat 的所有客户端
       │  ws://127.0.0.1:12451/api/chat        （标准 blivechat 端点）
       ▼
NanaType blivechat 客户端（crates/blive/src/client.rs）→ 弹幕面板、历史记录
```

（彗星号クライアントまたは OBS のブラウザソースがプラグインページを読み込み、postMessage で `LIVE_OPEN_PLATFORM_DM` / `SEND_GIFT` / `SUPER_CHAT` / `GUARD` を受け取って `toBlivechat()` で blivechat フレームに変換し、ページ側から NanaType のローカル中継へ接続します。中継はトークンを確認し、メッセージ id で重複を除いて `/api/chat` の全クライアントに転送します。NanaType 自身の blivechat クライアントもその 1 つで、コメントパネルと履歴に流し込みます。）

- ブラウザのページは接続を開始できるだけでポートを待ち受けられないので、間にサーバーが必要です。中継は blivechat の `/api/chat` を外部に提供しているので、blivechat 互換のほかのツールも接続して同じコメントを読めます。
- 中継は `127.0.0.1` だけで待ち受けます。送信側は設定ページで生成した 128 ビットのトークンを付ける必要があり、付いていなければハンドシェイクの時点で 401 を返します。同じパソコン上のほかの Web ページがコメントを偽造するのを防ぐためです。トークンは設定ページで再生成でき、その時点で古いアドレスは無効になります。
- 同じキャンバスが彗星号のプレビューと OBS の両方で読み込まれ、同じイベントが 2 回送られることがあります。中継は直近 1024 件のメッセージ id を覚えていて、1 回だけ転送します。
- プラグインは設定モード（`?env=1`）では接続と状態表示だけを行い、転送はしません。設定中の模擬データが NanaType に送られるのを防ぐためです。配信モードではページは完全に透明です。

## 使い方

1. NanaType：**設定 › 外部コメント** で **外部コメントを受信** をオンにし、**受信元** で **彗星号** を選びます。
2. プラグインページはリポジトリの `integrations/comet/index.html` です。設定ページではプラグインファイルを提供していません。公開者がワークショップにアップロードし、配信者はそこから追加します。
3. 彗星号の公式サイトにログインしてワークショップに入り、作品の種類で「自定插件」（カスタムプラグイン）を選び、`index.html` をアップロードして下書きに保存します。非公開の作品は審査なしで自分の作品集から使えます。設定項目が必要なら、`integrations/comet/settings.json` の内容を「自定义作品配置」（カスタム作品設定）に貼り付けてください。「NanaType 连接地址」（NanaType 接続アドレス）の入力欄が追加されます。
4. プラグインを配信キャンバスに追加し、右側の設定欄に NanaType の設定ページに表示されている接続アドレスを貼り付けます。
5. 設定ページの状態が「彗星号 · 接続済み」になれば、彗星号が受け取ったコメントがコメントパネルに表示されます。

中継のポートはデフォルトで 12451 で、設定ページには表示されません。変更するときは設定ファイルの `integrations.blivechat.comet_port` を編集します。

設定項目を使わず、プラグインの URL の後ろに `?address=` パラメーターを付けて接続アドレスを渡すこともできます。

## フィールドの対応

| 彗星号のイベント | blivechat コマンド | 説明 |
| --- | --- | --- |
| コメント `message` | `2` ADD_TEXT（v1.10 配列） | `dmType = 1` はスタンプコメントで、画像は `emojiImgUrl` から取得。配信者 / モデレーター / 艦長はそれぞれ authorType 3 / 2 / 1 |
| ギフト `gift` | `3` ADD_GIFT | `totalCoin = 単価 × 個数 × 1000`（金瓜子、1000 = ¥1）。無料ギフトは `totalFreeCoin` に計上。ブラインドボックスは出たギフトで計上 |
| スーパーチャット `superChat` | `5` ADD_SUPER_CHAT | `price` の単位は元 |
| 大航海 / 守護 / メンバーシップ `guard` | `4` ADD_MEMBER | `total_coin = 価格 × 1000`、`unit` は `guardUnit` から |
| 入室、いいね、配信開始、配信終了 | — | blivechat プロトコルに対応するコマンドがないため無視 |

ファンメダルは着用しているときだけ付けます。Bilibili 以外のプラットフォームのユーザー uid にはプラットフォームのプレフィックス（`dou_yin:…` など）を付け、Bilibili の uid と衝突しないようにしています。

## テスト

```bash
node --test integrations/comet/convert.test.mjs
cargo test -p nanatype-blive
```

`integrations/comet/fixtures.json` は両方のテストで使います。Node のテストはプラグインページの変換結果を確認し、Rust のテストはそのフレームをクライアントが期待どおりのイベントとして読み戻せるかを確認します。`scripts/comet_publish.mjs` はページ自身の変換関数を使って、実行中の中継にサンプルを送ります。各サンプルを 2 回ずつ送るので、重複除去の効果をそのまま確認できます。

## 未検証の点

彗星号クライアントに埋め込まれたブラウザが `ws://127.0.0.1` への接続に追加の制限（CSP、ローカルネットワークアクセスの確認）を設けているかどうかは、実際の彗星号クライアントにプラグインをアップロードして確認する必要があります。ブロックされた場合、プラグインは設定モードで「未连接」（未接続）と表示します。
