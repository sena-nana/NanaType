# 統合パッケージと機能プラグイン

スキン・リソース・サウンド・Lua をまとめたパッケージの形式と、Lua API 2 の実装リファレンスです。利用者は「セキュリティとライフサイクル」を、開発者は API とサンプルを先に確認してください。

**このページの案内**：パッケージ形式 → Lua API → 宣言データとログ → セキュリティ → デバッグと検証

パッケージの基本ファイルは次のとおりです。

- `package.toml`：識別情報、機能、依存関係を定義します。
- `skin.toml`：スキンのスタイルを定義します。
- `capabilities`：`skin`、`resources`、`lua`、`sounds`（[サウンドパック](skins.md#サウンドパック)）を組み合わせます。

内蔵スキンとユーザーパッケージは同じ形式・同じ検証ルールを使います。内蔵リソースはビルド時に解析され、実行時にも同じルールで検証されます。開発用ディレクトリはリロードのたびに読み直します。スキン ID は選択・索引・依存解決にのみ使われ、描画の判断には関与しません。

形式は `format = 1`、`schema = 3` です。パッケージはデータディレクトリの `packages/` に保存されます。Steam 版のワークショップ項目は読み取り専用の外部ディレクトリから読み込み、`packages/` にはコピーしません（[Steam 版](steam.md)）。旧形式と旧 `skins/` ディレクトリは自動移行・削除されません。

依存関係は `[dependencies]` に厳密な 3 桁バージョンで記述します。リソース参照はパッケージ内の相対パス、または `pkg:<パッケージ ID>/<パス>` を使います。フォントは `builtin:fonts/...` で参照できます。依存の欠落・競合・循環、範囲外の参照は読み込み時に拒否されます。書き出し時は依存パッケージと素材のライセンスを `dependencies/<パッケージ ID>/` に同梱します。

## Lua API 2

機能パッケージでは、さらに `capabilities = ["lua"]` と `[lua]` テーブルを宣言します。`entry` は UTF-8 ソースのエントリーポイント、`reads` はスクリプトが読み取れる宣言データの一覧です（既定は空）。スクリプトは値型のイベントだけを受け取り、宣言的なビューを返します。アプリ内部のオブジェクトや Rust のメッセージ列挙型には触れません。

```toml
[lua]
entry = "main.lua"
reads = ["phrases"]          # このパッケージのデータ。依存パッケージのデータは "pkg:<パッケージID>/<データID>"

[data.phrases]
path = "data/phrases.json"
format = "json"              # text・json・nthz。拡張子ではなく宣言に従って解析
format_version = 1
source = "作者自制"
license = "MIT"
constraints = { type = "object", required = ["phrases"], max_depth = 3 }
```

```lua
local count = 0
return {
    on_event = function(event)
        if event.type == 'line_start' then count = count + 1 end
    end,
    view = function()
        return {views = {{slot = 'panel', root = {
            kind = 'text', id = 'counter', text = tostring(count)
        }}}}
    end,
}
```

- イベントには `init`（`reads` に読み取り可能なデータが列挙される）、`data`、`command`、セリフ再生の開始・終了 `line_start`／`line_end`、`speaking`、`expression`、`portrait`、`shake`、`vts`、`chat_message`（プラットフォーム `blivechat`／`laplace`／`comet`／`twitch`、投稿者、プレーンテキスト）があります。イベントのフィールドはホストが生成済みのローカルな値で、アカウントの認証情報は含みません。
- `commands = {{id = 'reset', label = 'Reset'}}` でローカルコマンドを宣言します。ホストがコマンドの入口を表示し、実行されると元のプラグインに `{type='command', id='reset'}` を送り返します。コマンドから任意のアプリ操作を呼び出すことはできません。
- ビューのマウント先は `display`、`history`、`input`、`panel` で、それぞれ表示、履歴、入力のコンテンツ領域、プラグインパネルに対応します。汎用 UI は引き続き独立したニュートラルなテーマを使います。
- コンポーネントは `column`、`row`、`text`、`button`、`canvas` で、どれにも安定した一意の `id` が必要です。Lua 関数でこれらのノードを組み合わせて返せば、再利用できるコンポーネントを定義できます。
- コンテナは `children` を使います。`text` はリテラルテキストで、リッチテキスト・リンク・HTML は解釈しません。`button` は `command` でイベントを返し、ホストのボタンが備えるキーボード操作とアクセシビリティに対応します。
- `canvas` は `width`、`height`、`draw` を宣言します。描画は `rect`（`rect=[x,y,w,h]`、RGBA の `color`、`radius`）と `path`（`points`、`color`、`closed`、`width`）に対応します。描画とキャッシュはホストが行い、Lua が毎フレームの描画経路に入ることはありません。スキンの高度なエフェクトは、引き続き制限付きの WGSL インターフェースで表現します。

### 宣言データ

`nana.data.request(id, query)` は `reads` にあるデータしか要求できず、すぐにトークンを返します。結果は後からホストが `{type='data', results={{token=…, value=…}または{token=…, error=…}}}` イベントで届けるため、最初の `view()` の時点ではまだデータがありません。クエリは `{kind='info'}`、`{kind='whole'}`、テキストの `{kind='lines', start, count}`、JSON の `{kind='pointer', pointer='/a/0'}` と `{kind='slice', pointer, start, count}`、筆順データの `{kind='glyph', char='心'}` です。結果はただの値で、パス・ハンドル・ホストオブジェクトは含みません。JSON の `null` は Lua では `nil` になります。

ホストは、有効化に同意した時点の内容スナップショットから応答します。このデータは読み込み時に宣言された形式で完全に検証済みです。1 回のディスパッチで要求は最大 8 件、1 つのホストイベントにつき連鎖要求は最大 4 ラウンド、結果 1 件あたり 64 KiB、1 ラウンドの合計 120 KiB（エラー応答を含む）、`lines`／`slice` は 1 回あたり最大 1024 行です。予算を超えると切り詰めずにエラーを返すので、大きなデータは分割して問い合わせてください。次のホストイベントが届いた時点で未応答の要求は破棄されます。データ形式・制約・予算の詳細は[統合パッケージ全体設計](../package-design.md)を参照してください。

### ログ

`nana.log(level, message)` は NanaType のセッションログに 1 行書き込みます。`level` は `'debug'`、`'info'`、`'warn'`、`'error'` のいずれかで、それ以外はスクリプトエラーです。`message` は `tostring` で変換され、UTF-8 である必要があり、512 バイトを超えると文字境界で切り詰められます。1 回のディスパッチで保持されるのは最大 16 行で、超えた分は件数だけ数えます。さらにホストがプラグインごとに毎秒 10 行までに制限し、捨てられた行数は次の記録と一緒に書き込まれます。`debug` と `info` はユーザーが「詳細ログ」をオンにしたときだけ記録され、`warn` と `error` は常に記録されます。

ログは `[プラグイン ID] メッセージ` の形で書き込まれ、アプリ自身のログと同様にマスクされます。URL からはクエリ文字列が除かれ、Cookie やトークンのような値は `***` に、ホームディレクトリは `~` に置き換えられます。ユーザーが書き出す診断パッケージにはこれらの行も含まれるため、チャットの内容・アカウント・その他の個人情報は書き込まないでください。NanaType Editor のデバッガーではすべてのレベルが表示されます。ログ全体の設計は[ログ](logging.md)を参照してください。

インストール可能な完全なサンプルは `docs/examples/counter-plugin/` にあり、パッケージ済みの [counter-plugin.ntpkg](../examples/counter-plugin.ntpkg) は「プラグインとパッケージ」から読み込んで有効化できます。再生したセリフの数を数え、キャンバスのプログレスバーとリセットボタンを提供します。`docs/examples/phrase-plugin/`（[phrase-plugin.ntpkg](../examples/phrase-plugin.ntpkg)）では、JSON データを宣言して 1 文ずつ値で問い合わせる方法を示しています。ソースを変更したら `python scripts/assets/package-example-plugins.py` でアーカイブを作り直してください。

## セキュリティとライフサイクル

設定の「出所を確認して有効化を申請」では、作者、作成日、ライセンス、ライセンス対象、スクリプトのエントリー、読み取り可能なデータ（所属パッケージ、形式バージョン、サイズ、出所、ライセンス、署名で保護されているか）、パッケージの場所、署名の状態、内容の指紋を順に表示します。ユーザーは出所が信頼でき、リスクを理解したことを示すチェックを自分で入れてから「同意してこのプラグインを起動」を押す必要があります。確認するまでコードは実行されません。旧設定にある有効化済み ID から新しい信頼記録が作られることはありません。同意の記録にはポリシーのバージョンが付き、ポリシー 2 で宣言データの読み取りが加わったため、それ以前の同意は再確認が必要です。同意はパッケージと依存の内容全体に結び付くので、更新後は改めて確認が必要です。無効化すると同意も取り消され、再読み込みで再利用できるのは現在の内容とまだ一致する同意だけです。実行中のプラグインのパッケージや依存ディレクトリがディスク上で変わると、ホストはバックグラウンドで内容の指紋を再計算し、起動時と一致しなければそのプラグインを終了して再確認を求めます。

`package.toml` の `author`、`created_at`（任意、`YYYY-MM-DD`）、`licensed_to`、`license` はすべての能力に共通して適用されます。ライセンス対象は作者が宣言した個人・団体・全ユーザーで、アカウントとは紐付けません。情報が欠けている場合は「未提供」と表示し、作者や作成日を推測することはありません。

任意の `package.integrity.json` は Ed25519 署名で、保護ポリシー、パッケージ内のファイル一覧、保護対象ファイルの BLAKE3 ダイジェストをカバーします。`package.toml` は必ず保護対象です。editable に指定したファイルは変更できますが、それ以外の保護内容や署名ポリシーが変わると読み込みを拒否します。依存パッケージはそれぞれ独立して署名を検証し、内容全体はさらに有効化同意の指紋でカバーされます。署名付きパッケージを書き出しても元の署名バイト列はそのまま残ります。ソースは常に読める状態で、UI では未署名・検証失敗・検証成功をはっきり区別し、スクリプトのエントリーが保護範囲に含まれるかどうかも表示します。

有効な署名が示すのは内容がその公開鍵と一致していることだけで、作者本人の認証ではありません。編集を許可したファイルが作者のオリジナルのままである保証もありません。署名を取り除くと「署名有効」の状態は保てず、内容の指紋も変わるため、以前の有効化同意は無効になります。この仕組みは暗号化でも、回避できない DRM でもありません。作者は[パッケージエディター](package-editor.md)（独立したプログラム NanaType Editor）で保護するファイルを選んで署名できます。秘密鍵はシステムの保護されたストレージにのみ保存されます。

公式アプリは固定の Lua インタープリター（Wasm）を同梱しており、作者が配布するのは UTF-8 の Lua ソースだけです。有効化した各プラグインは独立したワーカープロセスで動きます。リソースを読み込んだり参照したりしても、スクリプトが自動で実行されることはありません。無効化するとワーカープロセスが終了して対応するビューが外され、再読み込みでは新しいインスタンスが作られます。Lua のメモリ上の状態は保存されません。

インタープリターは WASI や OS の実装に接続されていません。コンパイル成果物のファイル・プロセスなどのインポートはすべて実行拒否に結び付けられ、環境インターフェースは空の環境だけを返し、ホストの環境は渡しません。プラグインにはネットワーク、ファイル、外部プログラム、クリップボード、アカウント、永続ストレージ、システムへのアクセス API がありません。`io`、`os`、`package`、`debug`、`require`、`load`、`loadfile`、`dofile`、`string.dump` はいずれも提供されず、スクリプトからネイティブモジュールやバイトコードを読み込んだり、インタープリターを差し替えたりすることはできません。ホストの UI プロトコルは URL・パス・任意のメッセージ送出を受け付けません。

既定の上限は次のとおりです。

- ソース 128 KiB、IPC 1 件 256 KiB、Wasm リニアメモリ 32 MiB。
- 1 回の実行につき 2000 万 fuel、約 50 ms の割り込み予算。
- コンポーネント 512 個、ネスト 32 階層、描画命令 2048 件。
- パス 1 本あたり 256 点、合計 8192 点、テキスト合計 16 KiB。
- キューのイベント 32 件、ビュー更新は毎秒約 30 回（予算いっぱいのキャンバスでは約 6 回）、有効なインスタンスは最大 8 個。

ホストは Lua C API でビューを直接読み取り、プラグインのコードやメタメソッドは実行しません。有限の数値、サイズ、テキスト長、ID の一意性、未知のフィールドを項目ごとに検証します。子プロセス側だけで済ませた検証は信用しません。予算の詳細は[プラグインの性能・予算・隔離](../plugin-performance.md)を参照してください。

ワーカーの起動は 15 秒まで待ち、通常のイベント応答期限は 200ms です。タイムアウト、クラッシュ、不正な応答があるとそのプラグインは終了し、プロセスはただちに回収されます。イベントが溜まった場合、ワーカーは続けて処理して最新のビューだけを公開し、途中の状態を UI で順に再生することはありません。固定インタープリターは Rust のビルド時にプリコンパイルされ、起動時にアプリに埋め込まれた成果物から読み込まれます。IPC、パッケージの確認、署名検証、読み込み・書き出しはすべてバックグラウンドで行われ、UI スレッドは待たされません。Wasmtime のトラップや捕捉されない Lua 例外はインスタンスを無効にし、エラー後は明示的に再読み込みする必要があります。Lua の `pcall` で通常のスクリプト例外は捕捉できますが、実行制限を回避することはできません。

OS レベルの隔離：macOS ではワーカーがリクエストを読む前に拒否優先の Seatbelt プロファイルを適用し、ファイル・ネットワーク・プロセス作成がいずれも拒否されることを macOS 上で確認済みです。Windows ではホストがワーカーをジョブオブジェクトに入れます。製品版アプリでのワーカープロセスの起動・停止・回収は確認済みで、ネイティブテストではさらにカーネル上の制限を照合し、子プロセスの作成拒否、256 MiB のコミットメモリ上限、ジョブハンドルを閉じた後の終了を確認しています。デスクトップやクリップボードなどの UI 制限は現在のところ設定の照合のみで、破壊的なシステム操作を一つずつ実行しての確認はしていません。AppContainer は未実装で、ジョブオブジェクトはファイルとネットワークを隔離しません。現在の予算、測定方法、検証範囲は[プラグインの性能と隔離](../plugin-performance.md)を参照してください。

## デバッグ

[パッケージエディター](package-editor.md)では、本番のプラグインと同じ独立ワーカープロセスで下書きのスクリプトをデバッグできます。デバッグには現在の内容を信頼する個別の確認が必要で、何か編集するとインスタンスは停止し、確認も取り消されます。テストイベントはユーザーが手動で送り、返されたビューはデバッグパネルにだけ表示されます。デバッグの確認は有効化の同意ではありません。書き出して読み込んだ後も、「プラグインとパッケージ」で確認して有効化する必要があります。

## 検証

`cargo test -p nanatype-plugins` は通常のイベント、使用できないシステムインターフェース、悪意のある入力、無限ループ、メモリ枯渇を検証し、`cargo test -p nanatype-theme` はパッケージ形式、依存、継承、読み込み・書き出し、スキン設定を検証します。すべてのスキンは引き続き、表示・履歴・入力のスクリーンショットと、既定および 300px の狭いウィンドウでのレイアウトチェックに合格する必要があります。

インタープリターの出所、チェックサム、ライセンスは `crates/plugins/runtime/README.md` にあります。プラグインを動かすのに、ユーザーが Lua、Node.js、Wasmtime をインストールする必要はありません。

実際のネットワーク、ファイル、プロセス、アカウントへアクセスできないことを、配布前に対象 OS の設定と実行環境で確認してください。プラグイン性能の予算と隔離境界は[プラグインの性能・予算・隔離](../plugin-performance.md)を参照してください。
