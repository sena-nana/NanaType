# パッケージエディター

NanaType Editor でスキン、リソース、効果音、Lua パッケージを安全に作成・検証・署名するための利用者向けガイドです。画面を使い始める方は「プロジェクトを開く」、配布前は「保護と署名」「保存と書き出し」を確認してください。

**このページの案内**：画面構成 → プロジェクトとファイル → パッケージ情報 → 署名とプレビュー → Lua デバッグ → 保存と書き出し → 検証

[#6](https://github.com/sena-nana/NanaType/issues/6) に対応します。形式と境界は[統合パッケージ全体設計](../package-design.md#编辑器与非目标)を参照してください。エディターは独立したプログラム **NanaType Editor**（`editor/`、別ビルド・別インストール）です。`crates/frame` のスキンレンダラー、UI コンポーネント、プラグインホストを NanaType と共有しますが、互いのコード・文言・リソースは含みません。NanaType には編集の入口がなく、エディターにはコメント、マルチプレイ、ステッカー、出力、ホットキーがありません。

エディターは内部の下書きと、その場に書き戻すフォルダープロジェクトに対応しています。編集しても、現在のスキン、インストール済みのパッケージ、プラグインへの同意、実行中のプラグインは変わりません。変更が反映されるのは、`.ntpkg` を書き出して NanaType の「設定 → プラグインとパッケージ」で読み込んだ後です。

## 画面構成

プロジェクトを開くと、ウィンドウはキャンバス中心のワークスペースになります（最小 960×600 論理ピクセル、初期 1440×900）。

- **ツールバー**：パッケージ名（クリックするとプロジェクトメニュー：「保存」「書き出し」「前回の保存に戻す」「新しいパッケージとして複製…」「閉じる」）、パッケージの種類、「元に戻す」／「やり直す」。右側にはワークスペースのレイアウト切り替え（「キャンバスの横にソースを表示」または「ライブプレビューを表示」）、サイドパネルの切り替え、書き出し、保存があります。アクセントカラーになるのは、未保存の変更があるときの保存ボタンだけです。ステージの見え方（ビュー、サイズ、動き、ズーム、背景、サンプルテキスト）はキャンバス上部のストリップにまとめています。
- **アクティビティバー**：「デザイン」「ファイル」「効果音」「データとパイプライン」「Lua」、下部に「パッケージ情報」「公開」。プロジェクトにない能力の入口は表示されません（スキンのみのパッケージには Lua がない、など）。現在の入口をもう一度クリックすると左パネルを折りたたみ・展開できます。各ワークスペースは最後に表示していたファイルに戻ります。
- **左パネル／中央／右インスペクター**：すべてのワークスペースが同じ三つを使います。左に対象の一覧（レイヤー、ファイル、効果音、Lua ソース、宣言済みデータ）、中央にエディターまたはフォーム、右に選択中のもののプロパティ（スキンのインスペクター、効果音のプレーヤー、Lua デバッガー、ライブプレビュー）。両側のパネルはドラッグで幅を変えられ、ワークスペースを切り替えても幅は保たれます。ウィンドウ幅が 1280 論理ピクセル未満のときは、左パネルが既定で折りたたまれます。
- **下部ドロワー**：問題の一覧（クリックでファイルと行に移動）と Lua のデバッグ記録。既定では折りたたまれており、ステータスバーから開き、上端をドラッグして高さを変えられます。デバッガーを開始すると記録が開きます。
- **ステータスバー**：問題の数、デバッグ記録の入口、プロジェクトの出所、保存・検証・署名の状態。

キーボード（Windows は Ctrl、macOS は ⌘）：`Mod+S` 保存、`Mod+E` 書き出し、`Mod+Z`／`Mod+Shift+Z` 元に戻す・やり直す（フォーカスのあるテキスト欄は自分の履歴を使います）、`Mod+F` ソース内を検索、`Mod+1`…`Mod+7` アクティビティバーの順のワークスペース、`Mod+B` サイドパネル、`Mod+J` 問題、`Mod+W` プロジェクトを閉じる、`F5`／`Shift+F5` Lua デバッガーの開始・停止。行に入力した値は Enter を押すか欄を離れると書き込まれ、選択（チェックボックス、リスト、色）は選んだ時点で書き込まれます。保存は進行中の書き込みを待つため、欄から直接保存しても入力は失われません。

配色はシステムのライト／ダークに従い、キャンバス領域は常にニュートラルな背景色です。

## データディレクトリ

エディターは NanaType のデータディレクトリ（Windows は `%APPDATA%\dev.sena-nana.nanatype`、macOS は `~/Library/Application Support/dev.sena-nana.nanatype`）を読み書きし、スタートページに現在のパスを表示します。

- `packages/`：NanaType にインストール済みのパッケージ。読み取り専用で、コピーの編集、複製、依存の同梱に使います。
- `package-drafts/`：手動で保存した下書き。`recovery/` の下には独立した自動復元スナップショットがあります。
- 署名鍵（DPAPI ファイル、またはキーチェーンの `dev.sena-nana.nanatype.package-signing`）。以前 NanaType で作成した鍵もそのまま使えます。
- `config/settings.json`：読み取り専用。既定ではパッケージ自身の既定値でプレビューし、「NanaType の個人設定を再現」を明示的にオンにしたときだけ個人設定を反映します。プロジェクトに書き戻すことはありません。

ポータブル版 NanaType のデータはプログラムの隣の `data/` にあり、`nanatype-editor --data <そのディレクトリ>` で指定します。ポータブル版のエディター自身もプログラムの隣の `data/` を使います。コマンドラインの `nanatype-editor <ファイル.ntpkg またはプロジェクトフォルダー>` でプロジェクトを直接開けます。もう一度起動すると絶対パスは開いているウィンドウに渡され、同じ未保存確認を経ます。NanaType とエディターは同時に実行できます。

## プロジェクトを開く

スタートページには新規作成、開く、下書き、NanaType にインストール済みのパッケージが並びます。

- **新規作成**：「スキンのみ」「リソースのみ」「Lua のみ」「サウンドパックのみ」「混在」から選び、パッケージ ID を入力します。テンプレートはそのまま検証に通ります。
- **プロジェクトフォルダーを開く…**：`package.toml` を含むルートディレクトリを選びます。保存するとそのディレクトリに書き戻します。インストール済みパッケージのディレクトリは書き込み可能なプロジェクトにはできません。ディレクトリの走査ではバージョン管理用のディレクトリを除外し、シンボリックリンクは拒否します。
- **.ntpkg を開く…**：壊れたパッケージも修復のために開けます。署名の検証に失敗した場合、ローカルファイルはすべて読み取り専用になります。
- **編集**（インストール済みのユーザーパッケージ）：インストール先からコピーを読み込みます。インストール先自体は書き換えません。
- **新しいパッケージとして複製**（内蔵パッケージを含むすべてのパッケージ）：新しい ID の派生コピーを作り、元の署名を外して `derived_from` を書き込みます。

NanaType で新しいパッケージをインストールしたら、「再読み込み」で一覧を更新します。既知のパッケージ ID を変えるには「新しいパッケージとして複製」（派生コピー）が必要で、ソースの編集にも同じ制限がかかります。派生の前には未確定のフォームを処理する必要があり、すべて同じ未保存確認を経ます。

## ファイル

「ファイル」ワークスペースの左側はファイルツリーです。鍵アイコンは署名で保護されたファイルを示し、`dependencies/` 以下の依存パッケージはすべて読み取り専用です。ツリーの上部には読み込み、新規作成・移動・置き換え、削除があります。中央に選択したファイルが表示され、右側にライブプレビューを残しておけます。テキストファイルは行番号付きのエディターで開きます。

- Lua・TOML・WGSL はインデントとコメントの切り替えに対応しています。
- 検索は大文字と小文字を区別せず、前へ・次へ・置換・すべて置換ができます。ファイルごとにカーソル、選択範囲、スクロール位置を保持します。
- TOML と JSON は整形でき、コメントとキーの順序はそのまま保たれます。

バイナリファイルには、内容から判別した形式、サイズ、BLAKE3 ダイジェスト、データ宣言にある出所とライセンスが表示されます。

ファイルは新規作成、移動、名前変更、置き換え、複数選択での読み込みができます。対象パス欄で、新規作成や名前変更後のディレクトリを指定します。読み込み先は開始時に選択していたファイルのディレクトリです（ルートのファイルを選んでいた場合は既定で `assets/`）。名前を変更すると参照への影響を表示し、認識できた宣言パスは自動で更新します。Lua／WGSL 内の文字列は手動で合わせるよう知らせるだけで、保護された参照があると操作は止められます。

画像は透明のチェッカー背景と、宣言済みの 9 スライスのガイドを表示できます。フォントはサンプル文字を、音声は長さを表示し、再生・停止・音量を操作できます。オーディオデバイスが起動するのは明示的に再生したときだけです。

素材を読み込むときはファイル名を保ちます。ホストはパス、サイズ、拡張子と内容の一致を確認します。たとえば `.png` は本当に PNG でなければなりません。

入力後の完全な検証は 300ms のデバウンス後に実行され、バックグラウンドのジョブは 1 つだけに保って最新版にまとめます。エラーがあると直前の有効なプレビューを残して古いことを示します。64 KiB を超えるソースの構文診断と大きなスキンのパイプライン一覧はバックグラウンドで更新し、入力経路には軽いチェックだけを残します。完全な検証は読み込みと同じ経路でバックグラウンドで実行し、依存、署名、スキン、データ、スクリプトのエントリーをカバーします。問題の一覧の項目をクリックすると、該当するファイルと行に移動します。

## パッケージ情報

フォームでは次の項目を変更できます。`package.toml` に書き戻すとき、それ以外の内容とコメントは保たれます。

- 多言語の名前と説明、タグ、カバー、最低バージョン、基本スキン
- バージョン、作者、作成日、ライセンス対象、ライセンス
- 能力
- 依存関係。1 行に 1 つ `パッケージID@厳密なバージョン` を書き、インストール済みのパッケージから選ぶこともできます。バージョンの欠落、ID の重複、不正なバージョンは行ごとにエラーになり、黙って無視されることはありません。

スキンまたは Lua の能力を有効にすると、最初のファイルが追加されます。依存はインストール済みのパッケージから下書きに同梱されます。

宣言データと処理パイプラインは、「データとパイプライン」ワークスペースのフォームで追加・編集・削除します。

- **データ**（`package.toml` の `[data.<id>]`）：ID、ファイルパス、形式、形式バージョン、出所、ライセンス、JSON 専用の制約（JSON オブジェクトを入力、空欄なら制限なし）。ファイルはパッケージ内に存在している必要があります。名前を変えると `[lua] reads` も追従します。
- 宣言データの即時診断、整形、編集モードは `format` で決まります。テキストデータは `.json` というファイル名でも JSON エラーとして誤検出されず、JSON データは `.txt` というファイル名でも整形できます。
- **パイプライン**（`skin.toml` の `[pipelines.<名前>]`）：名前、プロセッサー、各入力ポート、パラメーター。項目には登録済みプロセッサーの出力名と型も表示されます。入力にはデータ ID（依存パッケージのデータは `pkg:パッケージID/データID`）、または別のパイプラインにつなぐ `パイプライン名.出力` を書きます。パラメーターは 1 行に 1 つ `名前 = 値` です。

未確定のフォーム内容（不正な入力を含む）はプロジェクトのセッションに保存されるので、タブを切り替えても失われず、未保存の確認や復元スナップショットの対象になります。保存や書き出しの前には、これらの入力を適用するか破棄する必要があります。

書き込む前に `package.toml` を厳密に解析し、登録済みのプロセッサーに照らしてパイプラインを検査します（ポートの型、循環、深さ、パラメーターの範囲、参照データが宣言されていて形式が合っているか、マテリアルが出所を失っていないか）。今回の変更で新たにエラーが生じる場合は書き込まず、メッセージを表示します。書き戻しはその場で行い、ほかのキーとコメントは保たれます。`package.toml` や `skin.toml` が署名で保護されている場合、該当部分は読み取り専用です。解析できないパイプラインもそのまま一覧に表示し、ソースで修正する必要があることを注記します。

## 保護と署名

初めて署名するときは「このコンピューターの署名鍵を使う」を選び、鍵がなければ作成します。秘密鍵はシステムの保護されたストレージ（macOS はキーチェーン、Windows は DPAPI）にのみ保存され、パッケージ、ログ、プラグインに入ることはありません。それ以外のプラットフォームでは今のところ署名に対応していません。

保護するファイルにチェックを入れて署名します。`package.toml` は常に保護されます。署名後は次のようになります。

- 保護されたファイルは読み取り専用になり、ファイル一覧も固定されます。
- 編集可能なファイルを変更しても、署名の状態は正しく有効と表示されます。
- このコンピューターの鍵で署名したパッケージは、署名を外して変更し、再署名できます。
- ほかの鍵で署名されたパッケージは、派生コピーとして複製してからでないと変更できません。

署名が示すのは内容が署名時から変わっていないことだけで、作者本人であることは証明しません。

## プレビュー

プレビューは「デザイン」ワークスペース中央のキャンバスです。キャンバスの上には再生モード（「静止・停止」「再生」「動きを減らす」「高度な効果をオフ」）、「再再生」、ズームと「全体を表示」、背景、「キャンバス設定」（論理幅と高さの指定、「NanaType の個人設定を再現」）、現在適用されているレイアウト層があります。下には「サンプル話者」とテスト用のテキストがあります。ツールバーではビューポートのプリセット（「横向き」「縦向き」「狭いウィンドウ」「既定サイズ」）とビューを選びます。静止、再生、動きを減らす、高度な効果をオフ、再再生はいずれも専用の Stage を使い、キャンバスから離れると更新を続けません。

スキンが検証に通ると、実際のレンダラーで下書きを描画し、3 つのビューを切り替えられます。

- **表示ウィンドウ**、**履歴**：設定のスキンプレビューと同じです。
- **入力ウィンドウ**：入力ウィンドウでスキンプレビューをオンにしたときの入力欄（`dialogue` の `Source::Draft`）で、専用のサンプル下書きが入っています。サンプルのエディターはフォーカスを受け取らず、入力も受け付けず、メッセージを送ることもありません。

プレビューは NanaType のスキンページと同じ `nanatype_frame::ui::preview::stage` を使い、各サンプルはそれぞれ専用の `Stage` に描画されます。「ファイル」ワークスペース右側のライブプレビューもこのキャンバスを使います。

## プロパティとキャンバス

「デザイン」ワークスペースの左側は**レイヤー**です。`skin.toml` で宣言されたテーブル（継承された既定値を含む）を階層順に並べ、ダイアログボックスが先頭、配列テーブル（装飾など）は番号順に並びます。その下の「プレビューのパラメーター」は、テスト用の値だけを変更します。レイヤーを選ぶと右側の**インスペクター**にそのテーブルの値が表示され、キャンバスでもそのテーブルが描く部品（名前札、立ち絵、続行マーク、装飾）が選択されます。キャンバスで部品をクリックしても対応するレイヤーが選ばれます。

インスペクターは 1 行に 1 つの値を表示します。ローカルで宣言した値のラベルはアクセントカラー、継承値は控えめな色です。数値はドラッグで調整でき（1 回のドラッグで取り消し 1 回分）、色にはカラーピッカーがあり、スイッチは切り替えた時点で書き込まれ、その他の値は入力して Enter を押すか欄を離れると書き込まれます。「継承に戻す」はローカルの宣言を削除し、リンクアイコンはパラメーターのバインドを開きます。サブテーブルは行の末尾に並び、階層を順にたどれます。「フィールドを追加」では、パラメーター、グループ、プリセット、レスポンシブのテンプレートを使えます。

**高度なスキン**ではソースが正となります。ツールバーの「キャンバスの横にソースを表示」で中央をキャンバスと `skin.toml`／WGSL のソースに分割でき、レイヤーを選ぶとソースが該当するテーブルまでスクロールします。インスペクターのタイトル横のコードアイコンで、そのテーブルのブロックをソースで開けます。シェーダー、マテリアル、パラメーター、グループ、プリセットもすべてレイヤーとして表示されます。

キャンバスでは単一要素の選択、装飾の移動・拡大縮小、名前札・立ち絵・続行マークの移動ができます。装飾の追加、複製、削除、並べ替えはレイヤーパネルの上部にあります。矢印キーで移動、Shift で移動幅を大きく、Esc かウィンドウのフォーカスが外れるとドラッグを取り消します。1 回のドラッグで記録される取り消しは 1 回分です。

編集対象は「基本レイアウト」「横向き」「縦向き」「ブレークポイントルール」から選べます。プロパティにはローカルの上書きと継承値が表示され、「継承に戻す」でローカルの宣言を削除できます。プレビューには適用中のレイヤーの適用順が表示されます。配列を初めて上書きするときは、現在の層で有効な配列全体がコピーされます。レイアウトの形状は実際の描画ノードから取得し、操作はプレビューのズームに合わせて換算され、パーセント指定の長さは保たれます。ドラッグを確定する前に実際の解決結果を比較し、選んだ層がほかのレスポンシブ層に上書きされている場合は書き込みを拒否して、対象の切り替えを促します。パラメーターのバインドは明示的に解除しないと定数に変えられません。WGSL 内部の図形はソースで編集します。

ブレークポイントルールのレイアウトには、実行時と同じリテラル値の制限がかかります。継承した配列にパラメーターのバインドが含まれる場合、ルール層への確定は完全な検証で拒否され、元の内容が残ります。横向き・縦向きのレイアウトではパラメーターのバインドを残せます。

ローカルの宣言の変更には `toml_edit` を使い、ほかのフィールド、コメント、未知のフィールド、パラメーターのプレースホルダーを保ちます。ソースに構文エラーがある間は対応する視覚的な操作が止まり、ソースページで修正を続けられます。効果音ページは宣言プロパティの編集と素材の試聴を共用しています。シェーダーのノードグラフや Lua のブレークポイントデバッガーはありません。

## Lua のデバッグ

デバッグは次のルールで動きます。

- バックグラウンドの完全な検証では、独立した Wasm ワーカープロセスで Lua をコンパイルするだけでソースは実行しないため、スクリプトの信頼は不要です。
- 実際に実行する前にリスクの説明を読み、「現在のソースを確認し、デバッグプロセスでの実行を信頼します」にチェックを入れて初めて「開始」できます。
- スクリプトは本番のプラグインと同じ独立した Wasm ワーカープロセスで動き、同じサンドボックスと制限を受けます。ワーカーは、エディターが `--plugin-worker` 付きで自分自身を起動し直して得られます。
- システムプロセスの起動と回収はバックグラウンドで行われます。起動に失敗するとエラーを表示し、停止や変更の後は古い結果を無視します。
- デバッガーが送るのは選んだテストイベント（`line_start`、`line_end`、`speaking`、`chat_message`、またはカスタム JSON）だけで、編集可能なイベント列の再生とログの絞り込みに対応しています。
- 返されたビューとコマンドはデバッグパネルにだけ表示されます。
- どのファイルを変更してもスクリプトは停止して信頼は取り消され、スクリプトが自動で実行されることはありません。
- 無限ループ、予算超過のビュー、構文エラーはいずれもエラーで終了し、UI が固まることはありません。
- エラーの行番号はエントリーファイルに対応付けられ、クリックで該当箇所に移動できます。

## 保存と書き出し

| 操作 | 動作 |
|---|---|
| 保存 | 下書きは `package-drafts/` に、フォルダープロジェクトは元のディレクトリに書き戻します。ソースが先に検証に通っている必要はありませんが、未確定のフォームは先に処理する必要があります |
| 前回の保存に戻す | それ以降の変更をすべて破棄します |
| 閉じる／終了／別のプロジェクトを開く | 保存・破棄・キャンセルを常に確認します。保存が終わってから該当する操作を実行し、その間の新しい変更は未保存のまま残ります |
| 下書きを破棄 | 二重の確認が必要です。下書きだけを削除し、インストール済みのパッケージには影響しません |
| .ntpkg を書き出す… | 依存を同梱して完全な検証を行い、失敗した場合はファイルを書きません |

下書き、復元スナップショット、書き出しは、同じディレクトリの一時ファイルに書いてからアトミックに置き換えます。書き込みに失敗した場合は古いファイルが残ります。保存、素材の読み込み、完全な検証のダイジェスト、鍵へのアクセスはバックグラウンドで実行され、結果にはプロジェクトの識別子とバージョンが付きます。全体の元に戻す・やり直すはソース、フォーム、ファイル、署名、キャンバスをカバーし、署名と保護の状態も内容と一緒に戻ります。

編集が止まって 2 秒後に復元スナップショットを書き込みます。手動の保存点は上書きしません。次回起動時にスタートページで復元か破棄を選びます。フォルダープロジェクトのスナップショットは手動の保存点、元のパス、最新のディスクの基準をそれぞれ保持し、復元後に外部の変更を改めて確認します。

ディレクトリの監視では連続したイベントをまとめます。変更していないファイルはディスクに追従し、別々のファイルの変更は統合し、同じファイルが競合した場合はローカルを残す・ディスクを受け入れる・コピーを保存するから選べます。保存前に基準を再確認し、競合が未解決のまま上書きすることはできません。複数ファイルの保存にはアプリのデータディレクトリにある `directory-transactions/` のログとバックアップを使い、中断した場合は次に開いたときに復旧します。復旧が新しい外部の変更と競合する場合はログを残し、手動で処理できるようパスを報告します。

macOS のパッケージは `.ntpkg` のドキュメントタイプを宣言して Finder からのオープンイベントを処理します。Windows のインストーラーは「プログラムから開く」への登録を行い、ユーザーの既定のアプリは置き換えません。コマンドラインはディレクトリのパスも受け付けます。

## 検証

```sh
cargo test --locked -p nanatype-theme --features editor --lib
cargo test --locked -p nanatype-editor --lib --test package_editor --test editor_reliability --test editor_authoring_ui -- --test-threads=1
cargo run --locked -p nanatype-editor --example editor_perf
scripts/check-product-split.sh
cargo run -p nanatype-editor
```

GPU の UI テストは直列に実行され、`target/package-editor/` 以下に中国語・英語・日本語、960／1280／1440／1920px のスクリーンショットを生成し、デザイン、ファイル、効果音、Lua、データとパイプライン、パッケージ情報、署名の各ワークスペースをカバーします。信頼性テストは保存のバージョン、古い結果、不正なフォームの復元、署名の取り消し、ローカルの宣言と参照の操作、ディレクトリの競合、保存の中断をカバーします。28 種の内蔵スキンはテーマライブラリの読み込み、レスポンシブのスナップショット、往復テストをそのまま使います。

パフォーマンスのサンプルは、固定の大きなソース・大きな素材の負荷での edit + view の CPU 時間を記録するもので、ネイティブの入力遅延、GPU プレビューの更新、ドラッグのフレーム時間の代わりにはなりません。ネイティブの macOS／Windows のファイル選択ダイアログ、終了、IME、DPI 1／1.5／2、監視、音声、キーチェーン／DPAPI、システムのオープンイベント、最終的なインストーラーは、対象 OS の実機で別途確認してください。自動テストに通ったことは、すべてのプラットフォームでの動作を保証するものではありません。


## 検証

書き出し前に、プロジェクト内のソース、依存関係、署名、スキン、データ、スクリプトを検証します。自動検証の実行例は次のとおりです。

```sh
cargo test --locked -p nanatype-theme --features editor --lib
cargo test --locked -p nanatype-editor --lib --test package_editor --test editor_reliability --test editor_authoring_ui -- --test-threads=1
cargo run --locked -p nanatype-editor --example editor_perf
scripts/check-product-split.sh
```

自動テストは保存、復元、依存、署名、競合、レスポンシブレイアウトを確認します。ネイティブのファイル選択、IME、DPI、キーチェーン／DPAPI、音声デバイス、最終インストーラーは対象 OS で別途確認してください。
