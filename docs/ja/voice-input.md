# 音声入力

入力ウィンドウで音声を文字に変換し、下書きへ追記または自動送信する機能の使い方と制限を説明します。まずモードを選び、次に認識方式・言語・マイクを設定してください。

**このページの案内**：基本操作 → 認識方式と言語 → プライバシーとモデル → 実装上の制限 → テスト

入力ウィンドウ下部のマイクボタンで音声入力を開始・停止します。隣のメニューからモードの切り替え、認識の再開、設定画面を開く操作ができます。**設定 › 入力 › 音声** では認識方式・マイク・言語・待機秒数をまとめて設定し、ローカルモデルの管理も行えます。

音声モードは既存の「**編集して送信**」／「**ミラー（リアルタイム）**」とは独立しています。

- **手動編集**（初回のデフォルト）：確定した認識テキストが下書きに入り、送信はユーザーが行います。
- **自動送信**：話し終えてからデフォルトで 3 秒待ち（1〜10 秒で設定可能）、認識が完了していれば現在のセリフを送信します。再び話し始めるとカウントダウンはキャンセルされます。

キー入力、IME の変換、貼り付け、削除、元に戻す／やり直し、書式操作、フレーズの挿入、過去のセリフの呼び出しを行うと認識が一時停止し、そのセリフの自動送信はキャンセルされます。手動で送信に成功すると聞き取りが再開します。下書きを消去した場合や残した場合も「**認識を再開**」をクリックできます。カーソル移動、テキスト選択、リッチテキスト／ソース表示の切り替えだけでは一時停止しません。

開始時にすでに下書きがある場合、音声の結果は末尾に追加され、そのセリフは手動で送信する必要があります。認識設定を変更した場合も一時停止し、現在の下書きを先に手動で確定します。暫定の認識結果は入力ウィンドウのステータス欄に表示され、確定してから下書きに書き込まれます。認識テキストは常に通常の文字として挿入されるため、`[pause]` などと読み上げてもマークアップは実行されません。

オンにすると、入力ウィンドウがフォーカスを失ったり、非表示・最小化されたりしても聞き取りを続けます。トレイに現在の状態が表示され、そこから停止できます。アプリを再起動してもマイクが自動でオンになることはありません。一時停止、停止、デバイスエラー、アプリの終了で録音デバイスは解放されます。停止しても確定済みのテキストは残り、現在の下書きは送信されません。

自動送信は通常の送信経路を通るため、再生キュー、オンラインセッションの権限、有効にしているコメント同期に従います。送信が拒否された場合は下書きを残して一時停止し、自動での再試行はしません。コメント同期は実際の用途に合わせて設定してください。

## 認識方式と言語

「**システムを優先**」は、まず選択した言語に対応するシステム認識を使い、使えない場合はインストール済みのローカルモデルに切り替えます。システムかローカルを明示的に選ぶこともできます。

- **macOS**：Speech フレームワークの `SFSpeechRecognizer` を使用します。初回はマイクと音声認識の許可が必要です。システムがオンデバイス認識に対応していればデバイス上で処理し、それ以外の場合は Apple のオンラインサービスが使われることがあります。権限はシステム設定で管理できます。
- **Windows**：デスクトップ SAPI にインストールされた認識エンジンを使用し、MSIX は不要です。使える言語はシステムにインストールされたエンジンによって決まります。エンジンがない場合はローカルモデルを選べます。マイクが使えない場合は、Windows のデスクトップアプリ向けマイク権限とデバイスの接続を確認してください。
- **ローカルモデル**：Whisper base 多言語 Q5_1、59,707,625 バイト、CPU 推論で、Python や外部の認識プロセスは不要です。インストール後は音声がデバイスの外に出ることはありません。中国語・英語・日本語が先頭に表示され、その他の言語はバックエンドの対応リストに基づきます。言語の自動検出はローカルモデルのみで、翻訳は行いません。

デフォルトの認識言語は UI の言語に従います。認識中にバックエンドでエラーが起きても、結果の混在や重複を避けるため、別のバックエンドにそのまま切り替えることはしません。下書きは残るので、認識方式を変更してから続行できます。

モデルは「**ダウンロード／再試行**」で明示的にダウンロードするか、上流から入手した同じファイルを「**モデルファイルをインポート…**」でインストールします。キャンセルと削除に対応し、ダウンロード中は別のインストールを同時に開始できません。ファイルはアプリのデータディレクトリの `speech/ggml-base-q5_1.bin` に保存されます。ダウンロード／インポートはいったん一時ファイルに書き込み、検証に通ってからインストールされます。他のモデルや破損したファイルは拒否されます。

上流ファイル：[ggerganov/whisper.cpp](https://huggingface.co/ggerganov/whisper.cpp/blob/main/ggml-base-q5_1.bin)

SHA-256：`422f1ae452ade6f30a004d7e5c6a43195e4433bc370bf23fac9cc591f01a8898`

アプリは録音を保存せず、診断ログに認識テキストを書き込むこともありません。サードパーティのライセンスはアプリに同梱されています。`THIRD_PARTY_NOTICES.md` を参照してください。

## 実装と検証

録音、リサンプリング、音声区間検出は UI およびローカル推論スレッドから独立しています。入力はモノラル 16 kHz、VAD フレームは 20 ms、プリロールは 200 ms です。500 ms の無音で認識区間を終了し、区間は最長 20 秒で区切ります。長い文の間、ローカルモデルは 3 秒ごとに暫定結果の更新を試み、最終結果は暫定更新より優先されます。通常の送信後は聞き取りとモデルを再利用し、下書きのバージョン番号で古いタイマー処理を無効化します。自動送信の待機時間は認識区間とは独立しており、音声区間のタイムスタンプから計算します。

開始／停止の状態は認識フェーズから一元的に導出されます。待機中と完了済みの認識区間は 1 つの順序付きテーブルを共有します。モデルのコピー中にダイジェストを同時に検証するので、インストール後にファイルを読み直す必要はありません。音声フォーマットの変換とモノラルへのミックスは 1 回の処理で行います。

録音と推論は上限付きキューを使います。過負荷、デバイスエラー、認識のタイムアウトはいずれも一時停止して下書きを残します。セッションの世代番号で古いコールバックを隔離し、認識区間は音声の順序で結合して重複を除きます。入力のルーティングでは早い段階で編集バリアを設定し、タイマーと結果コールバックの両方でバリアを確認するので、IME が未確定のテキストを持っている間に自動送信されることはありません。

自動テストは、状態機械、設定の互換性、モデルの検証、編集キーの分類、本文中のマークアップのエスケープ、実際の入力／設定画面をカバーしています。実際のモデルファイルを使うテストは別途実行します。

```sh
NANATYPE_SPEECH_FIXTURES=/absolute/fixture/directory \
  cargo test -p nanatype-speech offline_fixtures -- --ignored --nocapture
```

ディレクトリには上記の固定モデルと `jfk.wav`、`zh.wav`、`ja.wav`（16 kHz、モノラル PCM16）を置きます。このテストは実際のローカルデコードを確認し、読み込み時間・推論時間・リアルタイム係数を出力します。実際のマイク、権限ダイアログ、システム認識の品質、長時間配信での受け入れ確認の代わりにはなりません。

### 実機で確認するとき

自動テストは状態機械、設定互換性、モデル検証、編集キー、マークアップのエスケープ、入力画面を確認します。利用環境では次の項目を別途確認してください。

- マイクの選択、権限ダイアログ、デバイスの切断と再接続。
- システム認識とローカルモデルの切り替え、選択した言語での認識品質。
- 長時間の入力、無音区間、自動送信、オンライン接続中の送信結果。
- OS ごとの音声デバイス解放と、アプリ終了後に録音が続いていないこと。

固定音声を使うオフラインテストはデコード経路の確認用であり、実際のマイクや長時間配信での認識精度を保証するものではありません。
