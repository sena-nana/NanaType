# Building from source

> **Purpose:** Build, test, package, and develop NanaType and NanaType Editor from source.
>
> **On this page:** [Requirements](#requirements) · [Checks and snapshots](#requirements) · [Packaging](#requirements) · [Project layout](#project-layout)


Building, testing, packaging and development helpers. For a feature overview, see the [README](../../README.en.md).

## Requirements

You need Rust 1.98+ and the Windows 10 SDK (for icons and version resources). NanaUI and nanalive-spout (the Spout2 sender) are referenced as GitHub remotes at pinned revs; cargo fetches them on the first build, so no local checkout is needed. Building nanalive-spout requires git (it pulls the Spout2 submodule).

WebM decoding uses a pinned libvpx: on Windows and Apple Silicon the first build downloads and verifies the upstream prebuilt static library, so nothing extra is needed at runtime. Intel Macs build it from source and need `brew install nasm` and `rustup component add llvm-tools`; other platforms that need a source build can enable the `shiguredo_libvpx/source-build` feature.

```bash
cargo run -p nanatype
```

The package editor is a separate program, NanaType Editor ([guide](package-editor.md)). It shares `crates/frame` with NanaType, but each is built and packaged on its own and neither contains the other's code or strings:

```bash
cargo run -p nanatype-editor
```

Development builds keep full debug info for workspace code but only line numbers for third-party dependencies, to cut debug data during compiling and linking. This doesn't affect app behavior, but debugging third-party dependencies won't show variables or types.

Releases use the `dist` profile by default: `opt-level = "s"`, thin LTO, a single codegen unit, and a separate PDB. `dist-small` uses `z` with the same features; the [performance comparison](../release-profile-performance.md) shows its portable package is about 2 MiB smaller, but CPU time in key scenarios rises by about 16%–27%, so it stays optional.

For everyday checks, `cargo check -p nanatype` avoids linking, and `cargo build -p nanatype --timings` shows compile times.

```bash
cargo test --workspace --exclude nanatype
```

Render offscreen snapshots of every window's UI (no desktop windows open):

```bash
cargo run -p nanatype --example snapshots -- target/snapshots nanatype.night ja-JP
```

Packaging (requires `nana-packager` and Inno Setup 6):

```bash
pwsh scripts/package.ps1
pwsh scripts/package.ps1 -Product editor
```

`-Product editor` packages NanaType Editor (`NanaTypeEditor-<version>-setup.exe` / `-portable.zip`) and only builds `nanatype-editor`. `sh scripts/check-product-split.sh` checks that the two programs' dependencies and features don't cross over (it runs in CI). For a smaller portable package use `pwsh scripts/package.ps1 -Portable -Profile dist-small`. The packaging script always disables incremental compilation for release builds and uses the lockfile; it stops if compiling, licensing or the release self-check fails. The portable package excludes the `data/` user data produced by the self-check — the app creates it on first run — while bundled fonts, decoders, the GPU fallback renderer and crash recovery are all kept.

On macOS, package `NanaType.app`, a zip and a dmg (requires `nana-packager`; the output is unsigned):

```bash
scripts/package-macos.sh
scripts/package-macos.sh --product editor
```

Syphon comes from the `nanalive-syphon` crate in the nanalive-spout repository and is statically linked into the program, so no `Syphon.framework` needs to ship alongside; the first build requires the Xcode Command Line Tools.

The full license text (including the Syphon Metal server notice) is in `Contents/Resources/THIRD_PARTY_LICENSES.txt`, generated by `scripts/macos-licenses.py` from the macOS target's dependencies.

When a `vX.Y.Z` tag is pushed, `.github/workflows/release.yml` runs both scripts on Windows and macOS, generates a signed update manifest and creates a draft Release; see [Checking for updates](updates.md).

The Steam edition is built with the `steam` feature: it has no update check, the skins and playback pages can reach Steam Workshop subscriptions, and settings are shared with the GitHub edition. Put the Steam IDs in an uncommitted `.cargo/config.toml` (see `.cargo/config.example.toml`), then:

```bash
pwsh scripts/package.ps1 -Steam
```

```bash
scripts/package-macos.sh --steam
```

See [Steam edition](steam.md) for details.

Development environment variables (only effective in debug builds or when set explicitly):

| Variable | Effect |
| --- | --- |
| `NANATYPE_DEBUG=1` | Records the session log at Trace level and writes all of it to disk (like "Detailed logs" plus Trace); see [Logging](logging.md) |
| `NANATYPE_DEMO=1` | Plays a sample line 1.5 seconds after startup (debug builds) |
| `NANATYPE_DEMO_MARKUP=<markup>` | Overrides the auto-played sample line (requires `NANATYPE_DEMO`) |
| `NANATYPE_EXIT_AFTER=<ms>` | Exits normally when the time is up (for measuring startup, flushing logs) |
| `NANATYPE_OPAQUE=1` | Makes the overlay windows opaque (debug builds) |
| `NANATYPE_PERF=<JSON file>` | On exit, saves each native window's presented / output frame counts, host callback times and available-work counts; the first 2 seconds are discarded |

For the render flow, frame scheduling and surface branches, see [Rendering pipeline](../rendering-pipeline.md); for render measurements, GPU timestamps, screenshot comparison and limitations, see [Rendering performance notes](../rendering-performance.md) (both in Chinese).

## Project layout

| crate | Contents |
| --- | --- |
| `crates/model` | Line document model: text segments, ruby, stickers, markers |
| `crates/markup` | Markup parsing and serialization, templates |
| `crates/playback` | Reveal timeline, player state machine, live-mirror diffing, queue |
| `crates/theme` | Skin packages: manifests, inheritance, validation, install and export |
| `crates/i18n` | Fluent strings (zh-CN / en-US / ja-JP) |
| `crates/settings` | Settings structure, version migration, atomic writes, window positions |
| `crates/audio` | Decoding, mixing and sample-accurate scheduling |
| `crates/bridge` | VTube Studio, OSC, WebSocket |
| `crates/twitch` | Anonymous Twitch IRC receiving, device-code sign-in and Helix sending |
| `crates/blive` | blivechat, LAPLACE Event Bridge and Comet (彗星号) clients (protocol parsing, decryption, connect and reconnect) |
| `crates/core` | Session logic: drafts, sending, continue, queue, history, rewind |
| `crates/p2p` | Steam sessions (up to 8 people), session ordering, reconnects and image forwarding |
| `crates/update` | Update checks: signed Release manifest, file proxies, verified downloads |
| `crates/frame` | Framework shared by both programs: skin rendering (display, history, input), UI components, skin preview, plugin host, media services and paths |
| `app` | NanaType: NanaUI host, windows, views, hotkeys, tray, Spout |
| `editor` | NanaType Editor: package editor, signing and isolated debugging |

The pure-logic crates don't depend on the UI framework and can be tested on their own.
